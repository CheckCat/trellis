# Позиция D: достаточность курса для профессии джуниор-HR-аналитика

> Раунд 2: severity и состав дефицитов обновлены в `critique-sufficiency.md`
> (D-2 передан C, D-3 понижен, D-6 отозван; актуальный список — там).

Адвокат фронта «достаточность». Дата: 2026-09-30. Все пути уроков — от
`courses/hr-analytics/`.

## Тезис

«Выпускник НЕ готов к реальной работе джуниор-HR-аналитиком: в курсе есть
критические пробелы относительно требований рынка». После проверки я вынужден
**сузить собственный тезис**: против брифа курса (аудитория — HR-специалист,
уже сидящий в компании ~150 человек; обещание — «сам ответит на типовой вопрос
руководителя про людей») blocker-пробелов не нашёл. Против полного рыночного
профиля «джуниор-HR-аналитик» пробелы есть — 3 major и россыпь minor, ни один
не blocker. Главные: **затраты на персонал/ФОТ/план-факт отсутствуют вовсе**,
**две из четырёх ног обещания (дашборд, выводы) существуют только на
самоотметке**, **чистка грязных данных доведена до «заметить», но не до
«починить»**.

## Falsifier и decisive_test

- **Falsifier.** Гипотеза умирает, если (а) каждая обязанность HR-аналитика
  1-го уровня из ≥2 независимых источников профиля профессии находит в курсе
  урок с проверяемой практикой, и (б) capstone проходит полный цикл
  «достать → посчитать → показать → сформулировать» с зачётом движка на каждом
  этапе. Проверено: (а) ложно — «план-фактный анализ затрат на персонал»
  (обязанность 1-го уровня по deynekina.ru) не покрыт ни одним из 74 уроков;
  (б) ложно наполовину — этапы 3–4 самоотметки.
- **Decisive test.** Дешёвая часть (выполнена): матрица «рыночный навык →
  манифест/уроки» по manifest.yaml + grep всех 74 уроков (`ФОТ`, `план-факт`,
  `затрат`, `Python`, `Power BI`, `значим`, `опрос`, `бенчмарк` и др.) —
  результаты ниже, нулевые совпадения перепроверены вариантами написания.
  Дорогая часть (исследователю): выборка 10–15 живых вакансий
  «HR-аналитик» без опыта/до 1 года на hh.ru, частота требований
  Python / Power BI / 1С:ЗУП / ФОТ / опросы. Если ФОТ-аналитика и Power BI
  встречаются в <20 % джуниорских вакансий — мои major понижаются до minor.

## Дефициты с severity

- **D-1 (major). Аналитика затрат на персонал отсутствует классом.** Ни ФОТ,
  ни план-факт, ни структура затрат: grep по всем урокам — «ФОТ» 0, «план-факт»
  0, «бюджет» только в бытовых смыслах (capstone-brief.md: «директор открывает
  бюджет» — и курс тут же уводит в текучесть). По deynekina.ru/position-hr-analyst
  «план-фактный анализ затрат на персонал, численности» — обязанность
  HR-аналитика **первого** уровня зрелости. Ирония: данные для этого в курсе
  есть (salary_history, 367 строк; README считает среднее/медиану/P90 окладов),
  не хватает только уроков. Типовой вопрос директора «почему растёт ФОТ?» —
  выпускник не ответит, а это ровно жанр обещания курса.
- **D-2 (major). Ноги обещания «показать на дашборде» и «сформулировать вывод»
  не имеют машинного зачёта.** Обе DataLens-практики (manifest.yaml:867–916) —
  `answer` по числам (23; «Продажи»; 4; 44,6; «ИТ»; 33), которые все уже
  посчитаны в модулях 1–3 и лежат в README; их можно вписать, не открыв
  DataLens ни разу. capstone-dashboard и capstone-story — самоотметки.
  Формально это предел локального движка (бриф честно говорит «проверяет
  результатом»), но следствие для достаточности прямое: сертификат курса не
  свидетельствует, что человек хоть раз собрал дашборд. Смягчение: чек-листы
  этапов подробные, «30-секундный тест на живом человеке» — хорошая практика.
- **D-3 (major, на границе minor). Грязные данные: курс учит «заметить», но
  останавливается перед «починить», и на игрушечном объёме.** Вся грязь
  карантинирована в ats_raw (47 строк из 1746 строк данных курса);
  sql-data-quality.md:47 прямо пишет про смешанные форматы дат: «само
  приведение — работа кропотливая и за рамками урока. Здесь важно другое:
  заметить». Первая реальная задача выпускника на своих данных будет именно
  «починить» (выгрузка 1С/ATS, грязь во всех таблицах, тысячи строк).
  Смягчение: excel-power-query честно даёт повторяемую чистку (дубли, пробелы,
  типы) — но смешанные форматы дат в PQ одним «привести к типу дата» не
  лечатся, а других инструментов курс не даёт.
- **D-4 (minor). Модуль 7 «по желанию» уносит ответ на собственный кейс.**
  Открывающий вопрос модуля — «кто уйдёт следующим?» — типовой вопрос
  руководителя; пропустивший теряет когорты, сезонность и модели риска, и
  вопрос остаётся без ответа. Внутри заявленного обещания (текучесть, скорость
  найма) — не дыра, поэтому minor.
- **D-5 (minor). Выводная статистика отсутствует терминологически.** Нулевые
  вхождения «значим*», «доверительн*»; forecast-experiments компенсирует
  качественно («разница в 5 п.п. — это один человек, то есть шум») — для
  компании в 120 человек это честнее p-value, но на собеседовании слова
  «статистическая значимость» у выпускника не будет.
- **D-6 (minor). Python — нет, Power BI — нет.** Для точки входа «Excel видел,
  формулами не владеет» отказ от Python оправдан (AIHR: вакансии начального
  уровня требуют advanced Excel, не data science). DataLens вместо Power BI —
  разумно для РФ 2026, но доля вакансий с требованием Power BI — исследователю.
- **D-7 (minor). Опросы проводятся кем-то другим.** eNPS считается по готовой
  таблице ответов; как собрать 40 ответов, обеспечить анонимность инструментом
  и что делать при доле ответивших 30 % — не тема ни одного урока.

Blocker-дефицитов не нашёл — фиксирую явно, после проверок: матрица из 17
рыночных навыков, grep по 9+ темам с вариантами написания, чтение capstone
(4 урока целиком), forecast-experiments, metrics-engagement, excel-case,
excel-power-query, README, skills.yaml, capstone-раздел manifest.yaml.

## Что покрыто хорошо (обязан признать)

- Полный цикл capstone реально существует: SQL-этап зачитывается `expected`
  c `ordered: true` (сводная по 8 отделам), метрики — `answer` из 4 полей
  с tolerance (manifest.yaml:1237–1316). Ноги 1–2 обещания проверены движком.
- Модуль 1 — уровень определения метрик («формула, период, кто включён»)
  выше многих платных курсов; расхождение 19,2 % vs 19,4 % двух формул
  текучести объяснено, а не спрятано.
- SQL-модуль перекрывает джуниорскую планку (CTE, generate_series показан
  с честным «писать такое не потребуется»).
- 152-ФЗ + обезличивание + «что нельзя в ИИ-сервисы» — на рынке курсов почти
  не встречается, а в работе HR-аналитика в РФ нужно ежедневно.
- forecast-experiments — редкий по честности урок об A/B в малой компании.

## Слабые места моей гипотезы (разбор честный)

1. **«Обещание курса — не трудоустройство».** Бриф (README.md:9–14) обещает
   HR-специалисту умение самому ответить на вопрос руководителя, а не оффер
   джуниор-аналитика. Против этого узкого обещания курс почти чист: текучесть,
   найм, дашборд, выводы — покрыты и по большей части зачитываются движком.
   Мой тезис держится только в рыночной рамке — и то на major, не blocker.
2. **«150 человек — и есть реальность аудитории».** Упрёк «игрушечный масштаб,
   десятки тысяч строк не показаны» слабее, чем кажется: в компании на десятки
   тысяч сотрудников джуна встретит команда аналитики и обученный стек, а
   аудитория курса — HR в компании как раз романшкиного размера. Остаётся
   только D-3 (грязь), он масштабом не лечится.
3. **«Ни один курс не даёт профессию без практики на своих данных»** — верно,
   и финал capstone-story честно отправляет выпускника «к данным вашей
   компании». Но это не индульгенция для D-1: затраты на персонал — не вопрос
   стажа, а отсутствующая глава.
4. AIHR прямо пишет: вакансии начального уровня требуют «advanced Excel», а не
   статистику и не Python — по этой планке курс рынок скорее превышает.

## Атаки на A, B, C (по одному сильнейшему возражению)

- **Против A («план дефектен»).** Порядок модулей metrics → Excel → SQL → viz
  воспроизводит реальную траекторию роста HR-специалиста (сначала понять
  метрику, потом инструменты по возрастанию силы), словарь и порядок терминов
  сторожит машинный линт (0 ошибок, 0 предупреждений на старте дебатов), а
  skills.yaml связывает каждый навык с requires-цепочкой. Дефекты плана,
  которые может найти A, по построению лежат ниже порога, который линт не
  видит, — то есть это будут точечные шероховатости, а не дефектный план.
- **Против B («контент врёт»).** Все ключевые числа курса выведены одним
  детерминированным генератором (зерно 20251231), записаны в README рядом с
  породившими их запросами и прогнаны через живой API на фазе 5 — включая
  заведомо неверные попытки. Систематическое враньё чисел при такой методике
  маловероятно; B останется ловить формулировки, а формулировки я читал —
  расхождение двух формул текучести, «этап — максимальный достигнутый»,
  «termination_date — последний рабочий день» проговорены в явном виде.
- **Против C («задания не обучают»).** 28 машинно-зачитываемых практик с
  фазой 5 «эталон проходит, правдоподобно-неверное падает» — это выше планки
  типового курса, где практика вообще на честном слове. Сильнейший кандидат C
  — «DataLens-ответы можно списать из README» — является не дефектом дизайна
  заданий, а пределом локального движка без телеметрии внешних инструментов;
  внутри этого предела выбран самый строгий доступный зачёт (числа с
  tolerance, снятые с дашборда). Претензии C сведутся к границе возможного,
  а не к ошибкам автора.
