## Тезис

Гипотеза «контент содержит фактические ошибки; числа расходятся с данными "Ромашки"»
подтвердилась **в узком виде**: числа курса с данными НЕ расходятся ни в одном из ~40
пересчитанных показателей, но найден один воспроизводимо ложный технический приём
(Excel-формулы, дающие не те числа, что печатает урок, — доказано прогоном в настоящем
Excel) и три мелких фактических неточности. Тезис «курс учит неправде и его нельзя
выдавать» в сильной форме **не подтверждён**; в слабой форме — «до выдачи нужна правка
одного урока Excel и трёх мелочей» — подтверждён.

## Доказательства (дефекты с артефактами и severity)

### Д-1. major — excel-formulas.md учит формулам, которые в Excel возвращают другие числа

`courses/hr-analytics/lessons/excel/excel-formulas.md:22-23`:

```
=СЧЁТЕСЛИМН(E:E; "<>")   → 51 закрытая вакансия
=СЧЁТЕСЛИМН(E:E; "=")    → 4 ещё открыты
```

Данные верны (в `data/vacancies.csv` действительно 51 закрытая и 4 открытые — пересчёт
`awk -F';' 'NR>1 {if ($5=="") open++; else closed++}'` → closed 51, open 4), но
**формулы в напечатанном виде этих чисел не возвращают**:

- `E:E` — целый столбец, и критерий `"<>"` (непустые) считает и ячейку заголовка
  «закрыта» → Excel вернёт **52**, а не 51;
- критерий `"="` (пустые) по целому столбцу считает все пустые ячейки до конца листа →
  Excel вернёт **~1 048 521**, а не 4.

Артефакт — воспроизводимый прогон в Microsoft Excel на этой машине (osascript, столбец
E: заголовок + 3 значения + 1 пустая в диапазоне данных):

```applescript
tell application "Microsoft Excel"
  set nb to make new workbook
  tell active sheet
    set value of range "E1" to "закрыта"
    set value of range "E2" to "16.11.2024"
    set value of range "E3" to "09.04.2024"
    set value of range "E5" to "10.03.2025"
    set formula of range "G1" to "=COUNTIFS(E:E,\"<>\")"
    set formula of range "G2" to "=COUNTIFS(E:E,\"=\")"
    set r to {value of range "G1", value of range "G2"}
  end tell
  close nb saving no
  return r
end tell
-- результат: 4.0, 1.048572E+6  (заголовок посчитан в "<>"; "=" дал 1 048 572)
```

Усугубление: практика этого же урока («Сколько сотрудников работает сейчас?», эталон
120, manifest.yaml:347-349) по логике урока решается `=СЧЁТЕСЛИМН(H:H; "=")` — приём,
которому урок только что научил, вернёт ~1 048 391 и **провалит собственное задание
урока**; ученик обязан сам догадаться ограничить диапазон (H2:H186), чему урок не учил.
Соседняя формула `=СУММЕСЛИМН(I:I; E:E; 8; H:H; "=") → 4,5` при этом корректна
(пересчёт: 6 активных в Администрации, Σ ставок 4,5 — строки вне данных отсекаются
условием `E=8`), то есть дефект локализован ровно в двух строках 22-23.

Починка тривиальна (диапазон данных вместо целого столбца или `-1` на заголовок), но
без неё урок печатает «→ 51» и «→ 4» там, где инструмент выдаёт 52 и миллион, — это
ровно «курс учит неправде» в проверяемом виде.

исследователю, у меня нет интернета). Однострочная правка «как правило, не может…».

## Слабые места

1. Главный дефект (Д-1) — про поведение инструмента, а не про данные: числа 51 и 4
   сами по себе верны. Оппонент скажет «в русском Excel на диапазоне данных всё
   работает». Ответ: урок печатает конкретные формулы с `E:E` и конкретные ответы «→»;
   мой прогон в настоящем Excel даёт 52 и 1 048 572 — расхождение печатного и
   фактического есть определение фактической ошибки. Но признаю: это один урок, а не
   системная гниль.
2. Прогон Д-1 сделан на одной версии Excel (macOS этой машины); теоретически иные
   сборки могли бы вести себя иначе — falsifier: любая сборка Excel/Calc, где
   COUNTIF(целый столбец;"=") вернёт 4. Мне такая неизвестна.
3. Внешние утверждения (DataLens, Power Query/Mac) я не проверил — если исследователь
   найдёт там устаревание, мой фронт недосчитался дефектов; если не найдёт — курс ещё
   чище, чем я заявляю.
4. Гипотеза в сильной форме («учит неправде, нельзя выдавать») данными **опровергнута**:
   40+ сверок без единого числового расхождения — это лучший результат из трёх курсов
   репозитория, что я обязан признать честно.
