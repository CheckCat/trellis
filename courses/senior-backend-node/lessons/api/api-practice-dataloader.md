# Практика: DataLoader — батчинг и кэш на тик

Пишем механизм, который лечит N+1: загрузчик, собирающий ключи в пачку
в пределах одного тика цикла событий, выполняющий один батч-запрос и
раздающий результаты ожидающим. Это любимая задача live-coding для
тех, кто упоминает GraphQL: она проверяет и промисы, и понимание
микрозадач, и аккуратность с ошибками.

## Задание

Экспортируй фабрику `createLoader(batchFn)` и функцию `demo(keysets)`.

**Фабрика:**

```ts
type BatchFn = (keys: number[]) => Promise<(string | Error)[]>;

function createLoader(batchFn: BatchFn): {
  load(key: number): Promise<string>;
  stats(): { batches: number[]; }; // какие пачки реально ушли в batchFn
};
```

Правила загрузчика:

- `load(key)` возвращает промис значения этого ключа.
- Все `load`, вызванные **в одном тике** (синхронно или из
  микрозадач до планирования батча), собираются в одну пачку; батч
  выполняется отложенно (`queueMicrotask` / `process.nextTick` —
  выбери и оставайся последовательным: пачка уходит после того, как
  синхронный код и очередь микрозадач, набивших её, отработали).
- **Дубли ключей** в пачке схлопываются: `batchFn` получает уникальные
  ключи в порядке первого появления; оба вызова `load` с одним ключом
  получают одно и то же значение.
- **Кэш:** повторный `load` того же ключа в следующих тиках не ходит в
  `batchFn`, а возвращает закэшированный результат.
- `batchFn` возвращает массив той же длины, что пачка: значение или
  `Error` на позицию. `Error` на позиции — промис соответствующих
  `load` отклоняется этой ошибкой, **и она не кэшируется**: следующий
  `load` этого ключа снова пойдёт в батч.
- Если `batchFn` вернула массив другой длины — все промисы пачки
  отклоняются ошибкой `Error("batch length mismatch")`.

**Демо-функция** (её вызывает движок):

```ts
export async function demo(keysets: number[][]): Promise<{
  batches: number[][];
  results: (string | { error: string })[][];
}>;
```

`demo` создаёт загрузчик с `batchFn`, которая ведёт себя так: ключ
`k > 0` → значение `"v" + k`; ключ `k < 0` → `Error("no " + k)`; и
записывает каждую пачку. Затем для каждого набора `keysets[i]` — в
своём «раунде»: вызывает `load` для всех ключей набора синхронно,
дожидается всех результатов (`allSettled`), складывает их в
`results[i]` (`"v5"` или `{ error: "no -3" }`) и только потом
переходит к следующему набору. Вернуть — реально ушедшие пачки и
результаты по раундам.

## Пример

```js
await demo([[1, 2, 1], [2, 3]])
```

→

```json
{
  "batches": [[1, 2], [3]],
  "results": [["v1", "v2", "v1"], ["v2", "v3"]]
}
```

Первый раунд: три `load`, но пачка `[1, 2]` — дубль схлопнут. Второй
раунд: `2` взят из кэша, в базу ушла только `[3]`.

## Ловушки, которые проверяют случаи

- Дубли в одном тике — один поход за ключом, оба промиса получают
  значение.
- Кэш между раундами — повторный ключ не попадает в новую пачку.
- `Error` на позиции отклоняет только свои `load` и не кэшируется:
  в следующем раунде ключ снова в пачке.
- Пустой набор — пустой раунд без вызова `batchFn`.
