# Практика: обработчик с Idempotency-Key

Задача с реальных собеседований в финтех: «покажите, как сервер должен
обрабатывать повторы платежа». Пишем ядро — обработку последовательности
запросов с ключами идемпотентности, включая конкурентные повторы и
повтор с другим телом.

## Задание

Экспортируй функцию `processRequests(requests)`. Вход — массив
запросов **в порядке поступления**:

```ts
type Request = {
  id: string;          // номер запроса, для журнала
  key: string;         // Idempotency-Key
  amount: number;      // «тело» операции — сумма списания
  concurrentWith?: string; // id запроса, с которым пришёл одновременно
};
```

Модель исполнения: запросы обрабатываются по порядку массива. Если у
запроса указан `concurrentWith`, значит он пришёл, **пока указанный
запрос ещё выполнялся** (его результат ещё не сохранён).

Правила:

- Первый запрос с новым ключом **выполняет** операцию: списывает
  `amount`, результат — `charged:<amount>`.
- Повтор с тем же ключом и той же `amount` (не конкурентный) операцию
  не выполняет и получает **сохранённый** результат `charged:<amount>`
  с пометкой `replay`.
- Повтор с тем же ключом и **другой** `amount` — ошибка
  `key_reused_with_different_body`, операция не выполняется.
- **Конкурентный** запрос (`concurrentWith` указывает на запрос с тем
  же ключом) — ответ `in_progress`, операция не выполняется. Если
  `concurrentWith` указывает на запрос с другим ключом — это обычная
  обработка по правилам выше (конкурентность с чужим ключом не мешает).
- Запросы с разными ключами независимы, даже с одинаковой суммой.

Функция возвращает:

```ts
type Outcome = {
  log: { id: string; outcome: string }[]; // по каждому запросу, в порядке входа
  totalCharged: number;                   // сумма реально выполненных списаний
};
```

Значения `outcome`: `"charged:<amount>"`, `"replay:charged:<amount>"`,
`"error:key_reused_with_different_body"`, `"in_progress"`.

Заготовка:

```ts
type Request = {
  id: string;
  key: string;
  amount: number;
  concurrentWith?: string;
};

type Outcome = {
  log: { id: string; outcome: string }[];
  totalCharged: number;
};

export function processRequests(requests: Request[]): Outcome {
  // ...
  return { log: [], totalCharged: 0 };
}
```

## Пример

```json
[
  { "id": "r1", "key": "k1", "amount": 100 },
  { "id": "r2", "key": "k1", "amount": 100 },
  { "id": "r3", "key": "k1", "amount": 250 }
]
```

Результат:

```json
{
  "log": [
    { "id": "r1", "outcome": "charged:100" },
    { "id": "r2", "outcome": "replay:charged:100" },
    { "id": "r3", "outcome": "error:key_reused_with_different_body" }
  ],
  "totalCharged": 100
}
```

Списание одно: повтор вернул сохранённый ответ, а попытка использовать
ключ с другой суммой отклонена.

## Ловушки, которые проверяют случаи

- Конкурентный повтор (`concurrentWith` на запрос с тем же ключом) —
  `in_progress`, и деньги не списаны второй раз.
- После завершённого запроса обычный повтор — `replay`, а не
  `in_progress`.
- Разные ключи с одинаковой суммой — два независимых списания.
- Повтор с другой суммой не портит сохранённый результат: следующий
  повтор с правильной суммой всё ещё получает `replay`.
