# Практика: курсорная пагинация

Реализуем сердце keyset-пагинации — выборку страницы «после границы» с
непрозрачным курсором и признаком продолжения. На собеседовании это
просят как «сделайте пагинацию истории операций, чтобы не ездить
offset-ом».

## Задание

Экспортируй функцию `getPage(operations, cursor, limit)`.

- `operations` — массив операций по счёту, **не отсортирован**:

  ```ts
  type Operation = { id: number; createdAt: string; amount: number };
  ```

  `createdAt` — ISO-строка (`"2026-03-07T12:00:00Z"`); значения могут
  повторяться у разных операций, `id` уникален.
- `cursor` — строка-курсор с прошлой страницы или `null` для первой.
- `limit` — размер страницы, не меньше 1.

Правила:

- Порядок выдачи: **новые сверху** — по `createdAt` по убыванию, при
  равных `createdAt` — по `id` по убыванию.
- Страница — первые `limit` операций **строго после** границы курсора
  в этом порядке.
- Курсор — base64 от JSON `{"c":"<createdAt>","i":<id>}` последней
  операции страницы (используй `Buffer.from(...).toString("base64")` и
  обратно).
- Возврат:

  ```ts
  type Page = {
    items: Operation[];
    nextCursor: string | null; // null, если дальше ничего нет
  };
  ```

  `nextCursor` равен `null`, когда после последней операции страницы
  ничего не осталось (в том числе когда страница неполная).
- Испорченный курсор (не base64, не JSON, нет полей) — верни
  `{ items: [], nextCursor: null, error: "bad_cursor" }` (поле `error`
  добавляется только в этом случае).

Заготовка:

```ts
type Operation = { id: number; createdAt: string; amount: number };
type Page = { items: Operation[]; nextCursor: string | null; error?: string };

export function getPage(
  operations: Operation[],
  cursor: string | null,
  limit: number,
): Page {
  // ...
  return { items: [], nextCursor: null };
}
```

## Пример

Операции (уже мысленно отсортированы новые-сверху):

```
id=5 2026-03-07T12:00:00Z
id=4 2026-03-07T12:00:00Z   ← одинаковое время с id=5
id=3 2026-03-06T09:00:00Z
```

`getPage(ops, null, 2)` → items `[id 5, id 4]`, nextCursor — base64 от
`{"c":"2026-03-07T12:00:00Z","i":4}`. Второй вызов с этим курсором →
items `[id 3]`, nextCursor `null`.

## Ловушки, которые проверяют случаи

- Одинаковый `createdAt` у нескольких операций: граница различает их
  по `id`, ничего не теряется и не дублируется.
- Страница ровно в размер остатка: `nextCursor` обязан быть `null`,
  а не курсором в пустоту.
- Первая страница с `cursor: null`.
- Мусорный курсор — `bad_cursor`, не исключение.
- Вход не отсортирован — сортировка на твоей стороне.
