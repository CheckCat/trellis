# Финальная практика: брокер сообщений в памяти с consumer group

Выпускная работа курса: мини-Kafka в памяти. Топики с партициями по
ключу, публикация, подписка групп с распределением партиций, offset-ы
и commit. Это самая большая практика курса — час-полтора чистой
работы, ровно масштаб «звёздной» задачи финального live-coding. Всё
нужное ты уже писал по кусочкам; теперь — сборка.

## Модель

Один топик. Партиции нумеруются от 0 до `partitions - 1`. Сообщение
попадает в партицию `hash(key) % partitions`, где hash — сумма
кодов символов ключа (`[...key].reduce((s, c) => s +
c.charCodeAt(0), 0)`). Внутри партиции сообщения хранятся по порядку
публикации; у каждого — offset (позиция в партиции, с 0).

Группа потребителей: партиции распределяются между членами группы
**round-robin по порядку номеров**: партиция `i` достаётся члену
`i % размер_группы` (члены — в порядке подписки). У группы — свой
committed offset на партицию.

## Задание

Экспортируй функцию `runBroker(partitions, ops)`:

```ts
type Op =
  | { op: "publish"; key: string; value: string }
  | { op: "subscribe"; group: string; member: string }
  | { op: "poll"; group: string; member: string; max: number }
  | { op: "commit"; group: string; member: string; partition: number; offset: number };
```

Правила:

- **publish** — положить в партицию по ключу. Журнал:
  `"pub:p<номер>:o<offset>"`.
- **subscribe** — добавить члена в группу (повторная подписка того же
  имени игнорируется с журналом `"already:<member>"`); после
  добавления партиции перераспределяются по правилу выше. Журнал:
  `"assign:<member>:[p0,p2]"` — партиции члена по возрастанию (пусто
  — `"assign:<member>:[]"`). **Журнал assign пишется для всех членов
  группы** в порядке их подписки (ребалансировка видна целиком).
- **poll** — член читает из **своих** партиций до `max` сообщений
  суммарно: партиции обходятся по возрастанию номера, внутри
  партиции — с committed offset группы, по порядку. Прочитанное
  **не** коммитится само. Журнал: `"poll:<member>:<v1,v2,...>"`
  (значения в порядке чтения; пусто — `"poll:<member>:-"`).
- **commit** — группа фиксирует offset партиции: следующие poll
  начнут с `offset`. Если партиция не принадлежит члену — журнал
  `"reject:<member>:p<партиция>"` и никакого эффекта. Commit с
  offset-ом меньше уже закоммиченного — игнорируется (журнал
  `"stale-commit:p<партиция>"`). Успех: `"commit:p<партиция>:o<offset>"`.
- Повторный poll без commit возвращает **те же** сообщения (мы их не
  подтвердили — at-least-once в миниатюре).
- Верни `{ log: string[] }`.

## Пример

`partitions = 2`; ключ "a" (код 97) → партиция 1; "b" (98) → 0.

```json
[
  { "op": "publish", "key": "a", "value": "a1" },
  { "op": "publish", "key": "b", "value": "b1" },
  { "op": "publish", "key": "a", "value": "a2" },
  { "op": "subscribe", "group": "g", "member": "m1" },
  { "op": "poll", "group": "g", "member": "m1", "max": 10 },
  { "op": "subscribe", "group": "g", "member": "m2" },
  { "op": "poll", "group": "g", "member": "m2", "max": 10 },
  { "op": "commit", "group": "g", "member": "m2", "partition": 1, "offset": 2 },
  { "op": "poll", "group": "g", "member": "m2", "max": 10 }
]
```

Журнал:

```json
[
  "pub:p1:o0",
  "pub:p0:o0",
  "pub:p1:o1",
  "assign:m1:[p0,p1]",
  "poll:m1:b1,a1,a2",
  "assign:m1:[p0]",
  "assign:m2:[p1]",
  "poll:m2:a1,a2",
  "commit:p1:o2",
  "poll:m2:-"
]
```

Разбор: один член получает обе партиции; после подписки второго —
ребалансировка (p0 → m1, p1 → m2); m2 перечитывает партицию 1 с
нуля (никто не коммитил), коммитит offset 2 и дальше видит пусто.

## Ловушки, которые проверяют случаи

- Порядок гарантирован внутри партиции, не между: сообщения разных
  ключей в poll идут по партициям, не по времени публикации.
- Ребалансировка не сбрасывает committed offset-ы группы: новый
  владелец партиции продолжает с них (но незакоммиченное
  перечитывается — дубль, как в жизни).
- Commit чужой партиции отклоняется; stale commit игнорируется.
- Два члена группы никогда не делят одну партицию; третий член при
  двух партициях остаётся без назначения (`assign:<m>:[]`).
- `max` в poll режет суммарно по партициям.
