# Банк вопросов по всем модулям с короткими ответами

Инструмент финального повторения: по каждому модулю — вопросы,
которые звучат чаще всего, с ответом в одну-две строки и уроком, где
лежит развёрнутый разбор. Режим тренировки: закрой ответы, отвечай
вслух, свёртку сверяй; что не собралось за 30 секунд — иди в урок.
За вечер до собеседования — прогон целиком.

## Node.js

- **Однопоточный ли Node?** JS — один поток; процесс — нет: пул
  libuv (файлы, DNS, crypto), потоки V8, worker_threads. Сеть — без
  потоков, через epoll/kqueue. → node-runtime
- **setTimeout(0) против setImmediate?** Из главного модуля — не
  гарантировано; в I/O-колбэке setImmediate всегда раньше (poll →
  check). → node-event-loop
- **Рекурсивный nextTick?** Замораживает ввод-вывод: очередь
  дренится до конца. setImmediate — безопасная альтернатива. →
  node-event-loop
- **Что блокирует цикл и как найти?** Синхронный JSON/fs/crypto,
  регулярки, циклы; метрика — лаг цикла (perf_hooks). →
  node-blocking
- **pipe против pipeline?** pipe не пробрасывает ошибки и не убирает
  за собой; в проде — pipeline. → node-streams
- **write() вернул false?** Буфер выше highWaterMark: пауза
  источника до drain — это backpressure. → node-streams
- **Как искать утечку?** График heapUsed → воспроизвести → два
  снимка кучи → сравнение → retainers. rss растёт при ровной куче —
  внешняя память. → node-memory
- **uncaughtException — что делать?** Логировать и выходить:
  состояние не определено; «поймать и жить» — умножение бага. →
  node-errors-shutdown
- **Graceful shutdown?** SIGTERM → снять readiness → перестать
  принимать → дождаться in-flight → закрыть очередь/пул → выход; всё
  под общим таймаутом; keep-alive закрывать явно. →
  node-errors-shutdown

## HTTP-слой

- **Редкие 502 за балансировщиком?** Гонка keep-alive: таймаут
  сервера должен быть больше idle балансировщика. →
  http-server-anatomy
- **Async-ошибка в Express 4?** Теряется (unhandled rejection);
  обёртка catch(next); в Express 5 — исправлено. → express-middleware
- **Откуда скорость Fastify и что это стоит?** Схемы: компилированная
  валидация и сериализация (+ поля вне схемы ответа отсекаются),
  роутер-дерево, pino; цена — дисциплина схем. → fastify-model
- **Порядок конвейера Nest?** middleware → guards → interceptors →
  pipes → handler → interceptors → filters; «можно ли → в каком виде
  → сделать → оформить». → nest-pipeline
- **Чем плох Scope.REQUEST?** Заразен: пересоздаёт граф на запрос;
  контекст — AsyncLocalStorage. → nest-di-modules
- **Что нельзя отдавать в ошибке?** Stack, тексты драйверов, чужой
  message; наружу — код, человеческое сообщение, correlationId. →
  http-validation-errors

## API

- **401/403/404?** Не знаю кто / знаю и нельзя / на чужое приватное —
  404. → api-rest-design
- **Idempotency-Key — механика?** Ключ от клиента; сохранение ключа
  атомарно с операцией (уникальный индекс); повтор → сохранённый
  ответ; другое тело → 422; конкурентный повтор → ждать/409. →
  api-idempotency
- **Offset против cursor?** Offset читает и выбрасывает, нестабилен
  при вставках; keyset — WHERE по (значение, id), стабильно и дёшево;
  нет прыжка на страницу N. → api-pagination
- **Совместимые изменения API?** Добавлять поля/эндпоинты — да;
  переименование, смена типа, enum в ответе — нет; семантика без
  смены формы — худшее. → api-evolution
- **N+1 в GraphQL?** Резолвер на элемент → 1+N запросов; DataLoader:
  собрать ключи за тик, один batch, кэш на запрос. → api-graphql-grpc
- **Масштабирование WebSocket?** Соединения локальны, события
  глобальны: pub/sub мост между инстансами; sticky не решает
  доставку. → api-realtime

## PostgreSQL

- **Составной индекс — порядок колонок?** Равенства слева, диапазон/
  сортировка последними; работает слева направо. → pg-indexes
- **Почему индекс не используется?** Функция по колонке, чужой
  ведущий столбец, большая выборка, устаревшая статистика. →
  pg-indexes
- **Read Committed — какие аномалии?** Non-repeatable, phantom, lost
  update; dirty read в Postgres невозможен. Repeatable Read — снимок
  на транзакцию + ошибка сериализации (ретрай!). → pg-transactions
- **Чем вредны длинные транзакции?** Держат снимок — VACUUM не
  чистит, bloat; блокировки; соединение из пула. → pg-transactions
- **Очередь в Postgres?** FOR UPDATE SKIP LOCKED: воркеры берут
  незанятое без ожидания. → pg-locks
- **Оптимистичная блокировка?** version в WHERE и +1 в SET; 0 строк —
  409 и перечитать; для «человек думает между чтением и записью». →
  pg-locks
- **ADD COLUMN на 50 млн строк?** Блокировка тяжёлая, но мгновенная;
  страшна очередь за ней — lock_timeout и ретрай; NOT NULL — через
  CHECK NOT VALID; RENAME — никогда (expand/contract). → pg-migrations
- **Прочитал не то, что записал?** Лаг асинхронной реплики:
  read-your-writes — читать праймери после своей записи. → pg-scaling

## Auth

- **Сессии или JWT?** Люди в браузере — сессии (мгновенный отзыв);
  межсервисно — короткий JWT по JWKS; гибрид: cookie до BFF, JWT
  дальше. → auth-sessions-jwt
- **Ротация refresh и кража?** Refresh одноразовый; повторное
  использование → отзыв семейства (одной сессии); гонка вкладок —
  окно прощения. → auth-multisession
- **Контекст пользователя между сервисами?** Только подписанный
  (токен/exchange), не голый заголовок; сервисная identity —
  отдельно (client credentials/mTLS). → auth-service-to-service
- **Зачем PKCE?** Перехваченный код бесполезен без verifier. →
  auth-oauth-oidc
- **BOLA?** Чужой id при валидном токене; проверка принадлежности
  на каждом доступе, списки фильтруются запросом. → auth-security

## Кэш и Redis

- **Cache stampede?** Горячий ключ истёк — толпа в базу: склейка
  промахов, блокировка на пересчёт, вероятностное обновление, джиттер
  TTL. → cache-invalidation
- **Инвалидация по событию — удалять или обновлять?** Удалять:
  гонка перезаписи оставляет старьё навсегда. → cache-invalidation
- **Гарантия pub/sub Redis?** At-most-once, без хранения: отключился
  — пропустил; страховка — TTL; с гарантией — Streams. → cache-redis
- **Redis-замок правильно?** SET NX PX + случайный токен + Lua на
  снятии; пауза длиннее аренды → fencing token у ресурса. →
  cache-distributed-lock

## Очереди

- **Kafka против RabbitMQ?** Журнал фактов многим с replay и
  порядком по ключу — против очереди команд одному с ack,
  маршрутизацией, приоритетами. → queues-kafka
- **Exactly-once?** Транспортного нет; Kafka — внутри себя; внешний
  эффект — at-least-once + идемпотентность (= effectively once). →
  queues-guarantees
- **Порядок сообщений?** Только внутри партиции по ключу;
  конкуренция и повторы ломают; версия сущности спасает потребителя.
  → queues-guarantees
- **Outbox?** Событие — строкой в транзакции с бизнес-записью; реле
  публикует с повтором; дубли гасит потребитель; реле можно заменить
  CDC. → queues-outbox
- **Ядовитое сообщение?** Постоянные ошибки — сразу в DLQ (с алёртом
  и переигрыванием), не requeue; транзиентные — backoff + jitter +
  лимит. → queues-retry-dlq

## Архитектура

- **SOLID одним предложением каждый?** SRP — одна причина изменения;
  OCP — расширение без модификации (стратегии вместо switch); LSP —
  контракт, не сигнатура; ISP — узкие интерфейсы; DIP — домен
  зависит от абстракций. → arch-oop-solid
- **Ложный DRY?** Случайно похожее ≠ одно знание; флаг isUpdate —
  симптом; правило трёх. → arch-principles
- **Гексагональная?** Домен объявляет порты, инфраструктура —
  адаптеры; все стрелки внутрь; домен без импортов pg/kafka. →
  arch-layers
- **Агрегат?** Граница транзакции и немедленной согласованности,
  минимальный; между агрегатами — события; ссылки по id. → arch-ddd
- **Когда микросервисы?** По боли независимости команд/релизов;
  лестница монолит → модульный → сервисы; границы по bounded
  context; распределённый монолит — антиисход. →
  arch-monolith-microservices
- **CAP точно?** При разрыве — выбор C/A; P не выбирается; PACELC —
  ежедневный выбор латентность/строгость. → arch-consistency
- **Сага?** Локальные транзакции + компенсации (новые действия, не
  rollback); оркестрация для длинных, хореография для коротких; шаги
  идемпотентны. → arch-saga
- **ES против event-driven?** События как источник истины против
  событий поверх состояния; наш аудит — второе. → arch-cqrs-es

## Нагрузка и надёжность

- **Закон Литтла?** Конкурентность = RPS × латентность; им считаются
  инстансы, пулы, воркеры. → hl-capacity
- **Почему не среднее?** Хвост: p99 и усиление в цепочке (1−0,99ⁿ);
  гистограммы агрегируются, перцентили — нет. → hl-capacity,
  ops-metrics-tracing
- **Retry storm?** Ретраи множатся по этажам; бюджет ретраев, повтор
  на одном уровне, breaker. → hl-timeouts-retries
- **Состояния breaker-а?** Closed (окно, доля отказов при минимуме) →
  Open (мгновенный отказ, таймер) → Half-Open (пробы). →
  hl-circuit-breaker
- **Token против leaky bucket?** Всплеск при средней скорости —
  против выравнивания потока. → hl-rate-limiting
- **Consistent hashing?** Кольцо + vnodes; при смене узлов
  переезжает ~1/N против «почти всё» у hash % N. → hl-scaling
- **SLO и бюджет ошибок?** Цель по SLI на пользовательский путь;
  бюджет = разрешённый простой; сгорел — фриз рисков. →
  hl-failure-modes

## Эксплуатация

- **Три столпа?** Логи (что с запросом) — метрики (как системе) —
  трейсы (где время); связаны traceId. → ops-metrics-tracing
- **Liveness с проверкой базы?** Рестарт-шторм при сбое базы:
  liveness — тупой, зависимости — в readiness. → ops-docker-k8s
- **exit 137?** OOMKilled ядром: лимит контейнера против кучи V8 —
  max-old-space-size ≈ 75–80 %. → ops-docker-k8s
- **Blameless?** Защита информации: наказание за честность прячет
  причины; «почему система позволила». → ops-incidents
- **Что мокать?** Границы процесса: внешние API, время, случайность;
  свою базу — нет (testcontainers). → ops-testing
