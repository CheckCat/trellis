# Практика: перцентили и гистограмма из выборки задержек

Считаем то, о чём говорили два модуля: перцентили методом ближайшего
ранга и кумулятивную гистограмму в стиле Prometheus. Маленькая
задача на точность определений — и на собеседовании она вскрывает,
понимает ли человек, что такое p99 на самом деле.

## Определения (они и есть спецификация)

**Перцентиль методом ближайшего ранга**: p-й перцентиль выборки из N
значений — это элемент отсортированной выборки с рангом
`ceil(p / 100 × N)` (ранги с 1). Никакой интерполяции: p50 из
`[10, 20, 30, 40]` — ранг `ceil(0.5×4)=2` — значение 20.

**Кумулятивная гистограмма**: для границ бакетов `[b1, b2, ...]`
(по возрастанию) счётчик бакета `bi` — число значений `<= bi`
(кумулятивно, как `le` в Prometheus); последний бакет —
`+Inf` — всегда равен N.

## Задание

Экспортируй функцию `analyze(latencies, percentiles, buckets)`:

```ts
export function analyze(
  latencies: number[],     // задержки в мс, не отсортированы, могут повторяться
  percentiles: number[],   // какие перцентили посчитать, например [50, 95, 99]
  buckets: number[],       // границы бакетов по возрастанию, например [50, 100, 200]
): {
  count: number;
  percentiles: Record<string, number>;  // ключ — "p50", "p95"...
  histogram: { le: string; count: number }[]; // по бакетам + {"le":"+Inf"}
};
```

Правила:

- `percentiles` считаются методом ближайшего ранга по определению
  выше. Пустая выборка — валидный случай: верни `count: 0`, пустой
  объект перцентилей и гистограмму из нулей (включая `+Inf: 0`).
- Гистограмма кумулятивна: значение, равное границе, попадает в её
  бакет (`<=`).
- `le` в гистограмме — строка: `"50"`, `"100"`, `"+Inf"`.
- Вход не изменяй (не сортируй на месте — сделай копию); повторы —
  обычные значения.

## Пример

```js
analyze([120, 45, 250, 45, 80, 130, 500, 90, 60, 110], [50, 90, 99], [50, 100, 200])
```

Отсортированная выборка: `[45, 45, 60, 80, 90, 110, 120, 130, 250,
500]`, N = 10.

- p50: ранг ceil(5) = 5 → 90; p90: ранг 9 → 250; p99: ранг 10 → 500.
- Гистограмма: ≤50 → 2; ≤100 → 5; ≤200 → 8; +Inf → 10.

```json
{
  "count": 10,
  "percentiles": { "p50": 90, "p90": 250, "p99": 500 },
  "histogram": [
    { "le": "50", "count": 2 },
    { "le": "100", "count": 5 },
    { "le": "200", "count": 8 },
    { "le": "+Inf", "count": 10 }
  ]
}
```

Заметь: p90 (250) в 2,8 раза больше медианы (90) — тот самый хвост,
который среднее (144) прячет.

## Ловушки, которые проверяют случаи

- Один элемент: все перцентили равны ему.
- p100 — ранг N, максимум выборки (ceil(1.0 × N) = N).
- Значение ровно на границе бакета учитывается в нём (`<=`).
- Повторяющиеся значения — считаются столько раз, сколько встретились.
- Пустая выборка не падает.
