# Практика: consistent hashing

Строим кольцо из урока про масштабирование: виртуальные узлы,
детерминированная хеш-функция, выбор узла по ключу — и главное
свойство: при добавлении и удалении узла переезжает лишь малая часть
ключей. Его и проверим.

## Хеш-функция

Чтобы результаты сходились, хеш фиксируем (FNV-1a, 32 бита). У FNV на
коротких строках с общим префиксом слабая лавинность — виртуальные
узлы одного узла слипаются в дуги, — поэтому точку кольца считаем
**двойным** хешем: `point(s) = fnv1a(fnv1a(s).toString(16))`. Это
стандартный приём «перемешай ещё раз», и он же — ответ на вопрос
«почему ваши vnode-ы легли рядом».

```ts
function fnv1a(str: string): number {
  let hash = 0x811c9dc5;
  for (let i = 0; i < str.length; i++) {
    hash ^= str.charCodeAt(i);
    hash = Math.imul(hash, 0x01000193) >>> 0;
  }
  return hash >>> 0;
}
```

## Задание

Экспортируй функцию `demo(nodes, vnodes, keys, changes)`:

- `nodes` — исходные имена узлов; `vnodes` — виртуальных узлов на
  узел; `keys` — ключи для распределения.
- Кольцо: для узла `n` виртуальные точки — `point(n + "#" + i)` для
  `i` от 0 до `vnodes − 1`. Точки сортируются по значению хеша; при
  равенстве хешей (теоретически) — по имени узла.
- Ключ `k` попадает на первую точку с хешем `>= point(k)`; если
  таких нет — на первую точку кольца (замыкание).
- `changes` — последовательность операций:
  `{ op: "add" | "remove", node: string }`. После **каждой** операции
  пересчитай распределение и посчитай, сколько ключей сменили узел
  по сравнению с распределением **до этой операции**.

Верни:

```ts
type Result = {
  initial: Record<string, string>;   // ключ -> узел до изменений
  steps: { node: string; op: string; moved: number }[];
  final: Record<string, string>;     // ключ -> узел после всех изменений
};

export function demo(
  nodes: string[],
  vnodes: number,
  keys: string[],
  changes: { op: "add" | "remove"; node: string }[],
): Result;
```

## Что проверяется по смыслу

- Детерминизм: одинаковый вход — одинаковое распределение.
- Замыкание кольца: ключ с хешем больше всех точек уходит на первую
  точку.
- Локальность переездов: `moved` после операции — небольшая доля
  ключей (это свойство проверяется точными значениями на
  фиксированных данных — сравни сам с `ключи/узлы`).
- Удаление узла перемещает **только** его ключи: убедись, что при
  `remove` ключи, жившие на других узлах, остаются на местах (случаи
  подобраны так, что нарушение этого свойства даст другой `moved`).

## Подсказки без решения

- Держи кольцо массивом пар `[hash, node]`, отсортированным по hash;
  поиск — бинарный или линейный (ключей и точек немного).
- Пересобирай кольцо после каждой операции заново — оптимизация тут
  не нужна, важна корректность.
- `initial` считается один раз до операций; `moved` — сравнением
  словарей до/после операции.
