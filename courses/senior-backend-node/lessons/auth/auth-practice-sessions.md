# Практика: менеджер сессий с ротацией refresh-токенов

Собираем прошлый урок в код: менеджер многосессионной авторизации —
вход с устройств, ротация refresh, обнаружение повторного
использования с отзывом семейства, выход из одной сессии и из всех.
Это большое задание уровня «спроектируй и реализуй» — на
собеседовании такое дают на 40–60 минут.

## Модель

Время и генерация id внедряются, чтобы всё было проверяемо: операции
приходят списком, у каждой есть `at` — момент по модельным часам в
секундах. Id сессий и токенов выдаёт счётчик: первый созданный токен —
`"t1"`, второй — `"t2"`, и так далее; первая сессия — `"s1"`, вторая —
`"s2"` (счётчики раздельные).

Константа: refresh живёт **3600 секунд** с момента выдачи.

## Задание

Экспортируй функцию `runSessions(ops)`. Операции:

```ts
type Op =
  | { op: "login"; at: number; user: string; device: string }
  | { op: "refresh"; at: number; token: string }
  | { op: "logout"; at: number; token: string }
  | { op: "logoutAll"; at: number; user: string }
  | { op: "list"; at: number; user: string };
```

Правила:

- **login** создаёт сессию (`s<n>`) с устройством и выдаёт refresh
  (`t<n>`). В журнал: `login:<user>:<sessionId>:<tokenId>`.
- **refresh** с действующим токеном: старый токен помечается
  использованным, выдаётся новый (`t<n>`) **в той же сессии**; срок
  нового — 3600 с от `at`. Журнал: `rotated:<oldToken>-><newToken>`.
- **refresh** с токеном, который уже был использован, — кража:
  отзывается вся сессия (семейство). Журнал:
  `reuse-detected:<token>:revoked:<sessionId>`.
- **refresh** с истёкшим (прошло больше 3600 с с выдачи), отозванным
  или неизвестным токеном: журнал `denied:<token>`.
- **logout** по действующему токену завершает его сессию; журнал
  `logout:<sessionId>`. По недействующему — `denied:<token>`.
- **logoutAll** завершает все активные сессии пользователя; журнал
  `logout-all:<user>:<count>` (сколько завершили; 0 — тоже валидно).
- **list** — журнал `sessions:<user>:<s1,s2,...>` — активные сессии
  пользователя в порядке создания (или `sessions:<user>:-`, если
  нет).
- Отозванная или завершённая сессия делает недействующими все её
  токены.

Функция возвращает `{ log: string[] }`.

Заготовка:

## Пример: обнаружение кражи

```json
[
  { "op": "login",   "at": 0,   "user": "ivan", "device": "work" },
  { "op": "refresh", "at": 100, "token": "t1" },
  { "op": "refresh", "at": 200, "token": "t1" },
  { "op": "refresh", "at": 300, "token": "t2" }
]
```

Журнал:

```json
[
  "login:ivan:s1:t1",
  "rotated:t1->t2",
  "reuse-detected:t1:revoked:s1",
  "denied:t2"
]
```

Второй обмен `t1` — повторное использование: сессия s1 отозвана, и
даже «свежий» t2 больше не работает.

## Ловушки, которые проверяют случаи

- Повторное использование отзывает только свою сессию: параллельная
  сессия с другого устройства продолжает работать.
- Истечение по времени — `denied`, но **не** отзыв сессии: следующий
  login создаёт новую как обычно.
- `logoutAll` не трогает уже завершённые и считает только активные.
- `list` после отзыва показывает оставшиеся сессии.
- Токен завершённой через logout сессии при попытке refresh — просто
  `denied` (сессии уже нет; это не reuse-события).
