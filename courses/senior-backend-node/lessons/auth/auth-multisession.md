# Многосессионная авторизация: устройства, ротация refresh-токенов, отзыв

Уровень 1 и одна из тем, которые ты просил закрыть особо. Реальный
пользователь входит с трёх устройств, держит пять вкладок, теряет
телефон и жмёт «выйти везде». Спроектировать это — типовой вопрос
сеньорского собеседования, и дальше практика: менеджер сессий целиком.

## Боль: «сессия» — это не одна запись на пользователя

Наивная модель «у пользователя есть токен» рассыпается о быт:

- оператор работает с рабочего места и с ноутбука на удалёнке — выход
  на одном не должен убивать второй;
- клиент банка потерял телефон — нужно отозвать **именно тот**
  телефон, не разлогинивая остальное;
- служба безопасности хочет видеть список активных входов и убивать
  подозрительные;
- смена пароля обязана отзывать все сессии, кроме текущей.

Отсюда модель: **сессия — это устройство/вход**, у пользователя их
много. Каждая запись: id, пользователь, создана, последняя
активность, устройство/агент, адрес — и по ней возможны список,
выборочный отзыв, «выйти везде».

## Access + refresh

Стандартная пара, соединяющая скорость JWT и контроль сессий:

- **Access-токен** — короткоживущий (минуты, в банке 5–15), JWT:
  проверяется сервисами локально, не отзывается — его срок и есть
  предел ущерба.
- **Refresh-токен** — долгоживущий (дни–недели), **хранится на
  сервере** как часть записи сессии, предъявляется только identity
  и только чтобы получить новую пару. Он и есть «сессия устройства».

Выход = удалить запись refresh. «Выйти везде» = удалить все записи
пользователя. Список сессий = список записей. Access доживает свои
минуты — это осознанный компромисс, и его нужно проговаривать.

## Ротация refresh и обнаружение кражи

Правило: **refresh одноразовый**. Обмен пары выдаёт новый refresh, а
старый помечается использованным. Зачем — обнаружение кражи:

Токен украли (малварь, бэкап, перехват). Вором и жертвой refresh
теперь **двое**. Кто-то обменяет его вторым — и сервер увидит
**повторное использование** уже использованного refresh. Это сигнал
компрометации, и правильная реакция — отозвать **всё семейство
токенов**: цепочку, выросшую из этого входа (семейство = сессия
устройства). Жертва переlogin-ится паролем; вор остаётся ни с чем,
даже если успел обменять первым.

Тонкость, которую спрашивают: **гонка двух вкладок**. Обе проснулись,
обе шлют один refresh — вторая получает «уже использован», и по
строгому правилу мы отзываем семейство у честного пользователя.
Смягчения: короткое окно прощения (использованный токен принимается
секунды и возвращает **ту же** новую пару), или синхронизация
refresh между вкладками на клиенте (одна вкладка обновляет — ты
делал такое с фронта). Назвать гонку и смягчение — признак реального
понимания.

## Хранение в Redis

Схема, которую можно рисовать на собеседовании:

```
session:{sessionId} → {userId, deviceInfo, refreshHash, familyId,
                       createdAt, lastSeenAt, usedAt?}   TTL = жизнь refresh
user-sessions:{userId} → Set[sessionId]                  индекс для списка и «выйти везде»
```

Детали, которые отличают продуманный ответ:

- хранится **хеш** refresh-токена, не сам токен: хранилище — тоже
  место утечки;
- TTL записей = сроку refresh: мёртвые сессии убираются сами;
  индекс-набор чистится при чтении или фоновым проходом;
- `lastSeenAt` обновляется при обменах — по нему «неактивные 30 дней»
  отзываются политикой;
- смена пароля: удалить все записи из индекса, кроме текущей сессии.

Для «Пульта» поверх — банковская специфика: вход через SSO,
максимум N параллельных сессий оператора по политике, привязка
сессии к рабочей станции, аудит каждого входа и отзыва (событие в
Kafka — сервис audit подписан).

## На чём валят

- **«Отзыв access-токена»** — его не отзывают, он короткий; отзыв
  живёт на уровне refresh/сессии. Отвечающий «заведу чёрный список
  access» должен объяснить, чем это лучше сессий.
- **«Refresh в localStorage»** — самый долгоживущий секрет — в самом
  уязвимом месте; httpOnly cookie на путь обновления или хранение,
  недоступное скриптам.
- **Ротация без обнаружения повторного использования** — половина
  смысла ротации теряется: кража не детектируется.
- **Не назвать гонку вкладок** — тот, кто внедрял, о ней знает
  всегда.
- **«Семейство = все сессии пользователя»** — нет, семейство — одна
  цепочка (одно устройство); отзыв семейства не выкидывает другие
  устройства.

## Как ответить за минуту

«Сессия — это устройство: запись на каждый вход, у пользователя их
несколько; список, выборочный отзыв, выйти-везде — операции над
записями. Пара токенов: access — JWT на минуты, проверяется локально
и не отзывается; refresh — одноразовый, живёт в Redis как хеш в
записи сессии с familyId и TTL. Ротация на каждом обмене; повторное
использование использованного refresh — сигнал кражи, отзывается всё
семейство. Гонку двух вкладок решает окно прощения с выдачей той же
пары или синхронизация на клиенте. Смена пароля отзывает все сессии,
кроме текущей; каждый вход и отзыв — событие в аудит».
