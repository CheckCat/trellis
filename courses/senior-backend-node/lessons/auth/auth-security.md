# Безопасность API: OWASP, инъекции, секреты, заголовки, SSRF

Уровень 1 в объёме «минимум сеньора»: не пентест, а гигиена, которую
обязан знать каждый, кто выкатывает API. Вопросы отсюда любят
задавать «между делом» — и ответ мимо запоминается сильнее прочего.

## Боль: API ломают не через криптографию

Ломают через логику и небрежность: перебор чужих id, лишние поля в
теле, конкатенацию SQL, токен в URL. OWASP API Security Top 10 — их
каталог; разберём то, что стреляет чаще всего, на языке «Пульта» и
«Лавки».

## BOLA: чужие объекты по своему токену

Первая строка OWASP API. Авторизованный пользователь меняет id в
запросе — `GET /accounts/1234/operations` → `/accounts/1235/...` — и
читает чужой счёт: аутентификация есть, проверки принадлежности нет.
Синоним — IDOR. Лечение — прошлые два урока: `can()` с контекстом
объекта на каждом обращении к ресурсу, фильтрация списков в запросе,
404 на чужое приватное. Дополнительно — непредсказуемые id (uuid)
как замедлитель перебора, но **не** как защита: правило всё равно
проверяется.

## Инъекции

**SQL-инъекция.** Единственная защита — параметризованные запросы
(`$1`, плейсхолдеры ORM); конкатенация пользовательского ввода в SQL
запрещена без исключений. Отдельная ловушка — динамические **имена**
столбцов и направлений сортировки (`ORDER BY ${sort}`): параметром их
не передать, поэтому только белый список из кода (модуль API про
пагинацию это уже требовал).

**Командная инъекция** — `exec` с интерполяцией; использовать
`execFile`/`spawn` с массивом аргументов. **Path traversal** —
`../../etc/passwd` в имени файла; нормализация и проверка, что путь
остался внутри разрешённого корня. **NoSQL/jsonb-инъекции** — объект
вместо строки (`{"$gt": ""}`): лечится валидацией типов на границе —
ещё одна причина, почему схемы обязательны.

## Mass assignment и лишние данные

Тело `PATCH /users/me` с полем `role: "supervisor"` — и ORM
услужливо обновил роль, потому что код писал `update(req.body)`.
Лечение: белый список полей на каждом маршруте
(`additionalProperties: false` в схеме — из урока про Fastify).
Симметрично — **чрезмерная выдача**: отдавать в ответе всю запись «а
фронт возьмёт нужное» — способ утечь хешам паролей и внутренним
флагам; поля ответа — тоже белый список (схема ответа).

## SSRF

Сервис делает запрос по URL, на который влияет пользователь
(вебхук, «загрузить по ссылке», прокси картинок) — и злоумышленник
просит его сходить в `http://169.254.169.254/` (метаданные облака) или
во внутренний сервис без аутентификации. Лечение: белый список
хостов/схем, резолв и проверка адреса (запрет приватных диапазонов) с
защитой от DNS rebinding, исходящий прокси для таких запросов, и
внутренние сервисы, не доверяющие «своей сети» (zero trust из урока
про межсервисное).

## Секреты и логи

- Секреты — в хранилище, с ротацией (уже разбирали); проверка в CI на
  закоммиченный секрет (gitleaks и аналоги).
- Токены и пароли **не попадают в логи и URL**: URL живут в логах
  прокси, истории браузера, referer. Санитизация логов — явный
  список полей, которые маскируются.
- Ошибки наружу — без стеков и внутренностей (модуль HTTP).

## Заголовки и мелочи периметра

`helmet` ставит разумные дефолты: `Strict-Transport-Security` (только
HTTPS), `X-Content-Type-Options: nosniff`, `Content-Security-Policy`
для отдаваемого HTML, скрытие `X-Powered-By`. CORS — не безопасность
сервера, а инструкция браузеру: «разрешить чтение ответа этому
origin»; список origin-ов — явный, `*` с credentials не бывает. Rate
limiting на вход и чувствительные операции — был в auth-basics;
защита от ботов и WAF — на границе.

Зависимости: `npm audit`/Dependabot, lock-файл, минимум пакетов —
атаки через чужие пакеты реальны, и «у нас 2000 транзитивных
зависимостей» — тоже поверхность атаки.

## На чём валят

- **BOLA не узнать по описанию** — «а токен-то валидный» — значит,
  не понята сама проблема.
- **«ORM защищает от инъекций»** — параметризует значения, но не
  имена столбцов и не сырые запросы; `ORDER BY` из запроса — дыра.
- **«CORS защищает API»** — CORS ограничивает браузерное чтение
  ответов, серверу с curl он безразличен.
- **Токен в query string** — «удобно для отладки» и навсегда в логах.
- **update(req.body)** — mass assignment; белые списки обеих сторон.

## Как ответить за минуту

«Первое — BOLA: проверка принадлежности объекта на каждом доступе,
списки фильтруются запросом, на чужое — 404. Инъекции: только
параметризованные запросы, динамические имена столбцов — белым
списком, exec — только с массивом аргументов, пути — нормализация.
Mass assignment и утечки: белые списки полей запроса и ответа
схемами. SSRF: пользовательские URL — белый список, запрет приватных
диапазонов, исходящий прокси. Секреты — в хранилище, не в логах и не
в URL; helmet, явный CORS, лимиты на вход, npm audit в CI».
