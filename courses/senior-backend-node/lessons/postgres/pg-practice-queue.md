# Практика: очередь задач на SKIP LOCKED

Сервис фоновых задач хранит очередь в таблице `jobs`. Воркер
периодически забирает пачку задач: самые приоритетные из готовых к
запуску, не дерясь с другими воркерами за одни и те же строки.

## Задание

Напиши запрос воркера: выбери задачи со статусом `'queued'`, у
которых время запуска `run_at` не позже `'2026-03-07T10:01:00Z'`
(текущий момент воркера — литералом, никакого `now()`), возьми **три**
самые приоритетные (большее значение `priority` — приоритетнее), при
равном приоритете — раньше та, у которой меньше `id`.

Выведи два столбца в этом порядке: `id`, `kind`. Порядок строк — часть
ответа.

Чтобы воркеры не забирали одни и те же задачи, строки нужно
заблокировать с пропуском занятых: добавь к запросу
`FOR UPDATE SKIP LOCKED`. В песочнице ты один, поэтому на результат
это не повлияет — но проверка терпима к этой добавке, а в реальном
сервисе без неё запрос неверен: два воркера получат одинаковые пачки
и выполнят задачи дважды.

Подсказка без решения: условий в `WHERE` два — статус и время; дальше
сортировка по двум ключам и ограничение количества.
