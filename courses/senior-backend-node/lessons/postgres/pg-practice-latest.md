# Практика: последнее событие каждого обращения

Экран списка обращений показывает у каждого обращения его последнее
событие — «чем закончилось дело на данный момент». Взять «последнюю
строку на группу» — классическая задача SQL, и у Postgres для неё два
идиоматичных инструмента.

## Два способа

**Оконная функция.** Оконные функции считают по «окну» строк, не
схлопывая их в одну, как агрегаты. `row_number() OVER (PARTITION BY
case_id ORDER BY created_at DESC)` нумерует события каждого обращения
от новых к старым; последнее событие — строки с номером 1. Отбор по
номеру делается через подзапрос или CTE (`WITH имя AS (...)` —
именованный подзапрос, читающийся сверху вниз), потому что в `WHERE`
оконную функцию писать нельзя — она вычисляется позже.

**DISTINCT ON.** Расширение Postgres: `SELECT DISTINCT ON (case_id)
...` оставляет **первую** строку каждой группы в порядке `ORDER BY` —
поэтому сортировка обязана начинаться с `case_id`, а затем задавать,
какая строка «первая» (у нас — самая новая по `created_at`).

На собеседовании стоит знать оба: DISTINCT ON короче, оконные функции
переносимы и мощнее (ранги, скользящие суммы, `lag`/`lead` — «событие
до этого»).

## Задание

Выведи по каждому обращению его последнее по `created_at` событие —
три столбца в этом порядке:

1. `case_id`;
2. `kind` последнего события;
3. `created_at` последнего события.

Отсортируй результат по `case_id` по возрастанию. Времена событий
внутри одного обращения в данных не повторяются, так что «последнее»
однозначно.

Реши любым из двух способов — проверяется результат, а не приём. Если
выберешь DISTINCT ON, помни: внешний порядок по `case_id` у тебя уже
совпадает с требуемым; если оконную функцию — не забудь, что фильтр
по `row_number` живёт снаружи, в подзапросе или CTE.
