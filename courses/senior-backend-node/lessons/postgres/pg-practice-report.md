# Практика: отчёт по нагрузке операторов

Супервизору нужен отчёт: сколько **открытых** обращений сейчас на
каждом операторе и с какого времени висит самое старое из них.
Открытыми считаются статусы `open` и `in_progress`. Операторы без
открытых обращений обязаны попасть в отчёт — супервизор смотрит, кто
свободен.

## Задание

Выведи по каждому оператору три столбца, ровно в этом порядке:

1. имя оператора (`full_name`);
2. число открытых обращений (0, если их нет);
3. время создания самого раннего открытого обращения (NULL, если их
   нет).

Отсортируй по числу открытых обращений по убыванию, при равенстве —
по имени оператора по алфавиту. Порядок строк — часть ответа.

Подсказки без решения:

- Обращение связано с оператором полем `assignee_id`; у части
  обращений оно NULL — такие никому не принадлежат и в отчёт не
  входят.
- Оператор без обращений теряется при обычном соединении — подумай,
  какое соединение сохраняет всех операторов.
- Считать и брать минимум нужно только по открытым обращениям, при
  этом не теряя операторов, у которых их нет: условие на статус в
  `WHERE` отфильтрует и самих операторов — есть более точные места
  для этого условия (условие соединения или `FILTER`).
- `COUNT(c.id)` не считает NULL — это здесь полезно.
