# Практика: DI-контейнер с обнаружением циклов

Ядро Nest и Angular — контейнер, который по объявленным зависимостям
строит граф и создаёт каждый провайдер ровно один раз, в правильном
порядке. Написать его — популярное задание live-coding: в нём
проверяются обход графа, кэш созданного и аккуратная диагностика
цикла. Ты делал похожее для фронта — здесь добавляется требование к
формату ошибок.

## Задание

Экспортируй функцию `instantiate(providers, roots)`.

- `providers` — массив объявлений: `{ token: string, deps: string[] }`.
  Токены уникальны.
- `roots` — токены, которые нужно создать (аналог контроллеров).

Правила:

- Создание провайдера требует, чтобы **сначала** были созданы все его
  `deps` — в порядке их перечисления, рекурсивно.
- Каждый провайдер создаётся **не более одного раза** (синглтон), в
  каком бы количестве мест он ни требовался.
- Корни обрабатываются по порядку массива `roots`.
- Успех — вернуть `{ order: string[] }`: токены в порядке создания.
- Зависимость от несуществующего токена — вернуть
  `{ error: "unknown: <token>" }` (первый встреченный по порядку
  обхода).
- Цикл — вернуть `{ error: "cycle: A -> B -> ... -> A" }`: путь от
  первого токена цикла по рёбрам до его повторения. Диагностируется
  первый встреченный по порядку обхода цикл.
- Ошибка прекращает работу: частичный `order` не возвращается.

Заготовка:

```ts
type Provider = { token: string; deps: string[] };
type Ok = { order: string[] };
type Err = { error: string };

export function instantiate(providers: Provider[], roots: string[]): Ok | Err {
  // ...
  return { order: [] };
}
```

## Примеры

Цепочка и ромб:

```json
providers: [
  { "token": "controller", "deps": ["service", "logger"] },
  { "token": "service",    "deps": ["repo", "logger"] },
  { "token": "repo",       "deps": ["db"] },
  { "token": "db",         "deps": [] },
  { "token": "logger",     "deps": [] }
],
roots: ["controller"]
```

Результат: `{ "order": ["db", "repo", "logger", "service", "controller"] }`.
`logger` нужен и сервису, и контроллеру — создан один раз, в момент
первой надобности (глубже по обходу: внутри `service`).

Цикл:

```json
providers: [
  { "token": "a", "deps": ["b"] },
  { "token": "b", "deps": ["c"] },
  { "token": "c", "deps": ["a"] }
],
roots: ["a"]
```

Результат: `{ "error": "cycle: a -> b -> c -> a" }`.

## Ловушки, которые проверяют случаи

- Ромбовидная зависимость создаётся один раз, а не дважды.
- Провайдер, зависящий сам от себя, — тоже цикл: `cycle: a -> a`.
- Незнакомый токен в `roots` — та же ошибка `unknown`.
- Второй корень не пересоздаёт то, что уже создано первым.
- Порядок в `order` — глубина сначала, в порядке перечисления deps.
