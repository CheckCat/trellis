# Практика: параллельная обработка с порядком внутри ключа

Ядро серьёзного потребителя: сообщения разных сущностей можно
обрабатывать параллельно, сообщения одной — строго по порядку. Так
устроены партиции Kafka, per-key очереди в воркерах, и это же просят
написать на live-coding: «спланируй обработку, не смешав порядок
ключей».

## Модель

Обработка идёт **волнами**. В каждой волне можно выполнить не больше
`limit` сообщений (столько воркеров), и в одну волну не могут попасть
два сообщения одного ключа — внутри ключа обработка последовательна:
следующее сообщение ключа может пойти только в следующей волне после
предыдущего.

Сообщения берутся в порядке поступления: волна набирается проходом по
очереди оставшихся слева направо — сообщение попадает в волну, если
(а) в волне ещё есть место и (б) в **этой** волне ещё нет его ключа и
(в) все предыдущие сообщения этого ключа уже обработаны в прошлых
волнах. Сообщение, чей ключ занят или чья очередь внутри ключа не
подошла, пропускается (его догонят следующие волны), а обход
продолжается.

## Задание

Экспортируй функцию `planWaves(messages, limit)`:

```ts
type Message = { id: string; key: string };

export function planWaves(messages: Message[], limit: number): string[][];
```

Верни массив волн; волна — массив `id` в порядке набора. Продолжай,
пока все сообщения не распределены.

## Пример

```json
messages: [
  { "id": "a1", "key": "A" },
  { "id": "a2", "key": "A" },
  { "id": "b1", "key": "B" },
  { "id": "c1", "key": "C" },
  { "id": "b2", "key": "B" }
], limit: 2
```

Результат: `[["a1", "b1"], ["a2", "c1"], ["b2"]]`.

Разбор: волна 1 — `a1` (ключ A свободен), `a2` нельзя (A уже в
волне), `b1` (B свободен) — лимит 2 исчерпан. Волна 2 — `a2` (теперь
a1 обработан), `b2` нельзя: B свободен как ключ, но `b1` обработан, а
`b2` — следующий за ним... стоп, можно! Проверим правило (в): все
предыдущие сообщения ключа B (`b1`) обработаны в прошлых волнах —
значит, `b2` мог бы войти. Но обход идёт слева направо: после `a2`
следующий нераспределённый — `c1`, он входит, и лимит 2 исчерпан
раньше, чем очередь дошла до `b2`. Волна 3 — `b2`.

(Да, этот разбор — часть задания: правило «набор слева направо до
лимита» и правило «не смешивать ключ в волне» вместе дают ровно такой
результат.)

## Ловушки, которые проверяют случаи

- Сообщение ключа не может обогнать предыдущее сообщение того же
  ключа — даже если в волне есть место.
- Один ключ на весь поток при любом лимите — строго по волне на
  сообщение.
- `limit = 1` — волны по одному сообщению, в порядке допустимости, а
  не исходного массива (пропущенные из-за ключа догоняют позже).
- Пустой вход — пустой результат.
- Ключи с одним сообщением заполняют свободные места волн жадно.
