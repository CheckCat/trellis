# Практика: обращение и событие outbox в одной транзакции

Паттерн outbox руками, в песочнице: создать обращение так, чтобы
бизнес-запись, строка истории и событие для публикации появились
**атомарно** — одной транзакцией. Ровно этот код живёт в сервисе
`cases` на каждом создании обращения.

## Сценарий

Клиент Дарья Полякова (id 4) обратилась через чат: подозрительная
операция по её счёту. Создаём обращение со всеми спутниками.

## Задание

Одной отправкой, обернув все операторы в явную транзакцию
(`begin; ... commit;`):

1. Вставь в `cases` обращение: `customer_id = 4`, без назначенного
   (`assignee_id` NULL), `topic = 'disputed-operation'`,
   `status = 'open'`, `priority = 1`,
   `created_at = '2026-03-07T11:00:00Z'` (столбец `version` не
   указывай — у него default 1; `closed_at` — NULL).
2. Вставь в `case_events` событие создания: `case_id` — id нового
   обращения, `kind = 'created'`, `actor_id` NULL,
   `payload = '{"channel":"chat"}'::jsonb`,
   `created_at = '2026-03-07T11:00:00Z'`.
3. Вставь в `outbox` событие для публикации:
   `topic = 'case.created'`, `payload` — jsonb с ключом `caseId`,
   равным id нового обращения, `created_at = '2026-03-07T11:00:00Z'`,
   `published_at` NULL (реле опубликует и проставит само).
4. После `commit` — последним оператором выведи из `outbox` строки с
   `published_at is null`: `topic`, `payload` (увидишь и старое
   неопубликованное событие из seed, и своё).

Про id нового обращения: в песочнице перед попыткой ровно 20
обращений, так что новое получит id 21 — но код, который «знает» id
заранее, в проде мгновенно ломается. Возьми id по-настоящему:
`insert ... returning id` в CTE и используй его в следующих вставках
(`with new_case as (insert ... returning id) insert ... select ...
from new_case`), либо `currval(pg_get_serial_sequence('cases','id'))`
после вставки. Проверка сравнивает состояние базы с эталоном, где id
взят честно, — совпадёт и «21», но смысл задания в связке.

## Ловушки

- Атомарность здесь и есть задание: любая из трёх вставок поодиночке
  — это та самая «двойная запись», от которой outbox спасает.
- `payload` outbox — jsonb с числовым `caseId`
  (`jsonb_build_object('caseId', id)` или литерал с честным id).
- Ничего лишнего не меняй: сравнение состояния увидит любую
  постороннюю правку.
