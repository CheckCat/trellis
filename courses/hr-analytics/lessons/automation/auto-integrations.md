# Интеграции и выгрузки без кода: API, экспорт по расписанию

В ТЗ на автоматизацию есть раздел «данные-источники». Но как данные будут попадать из источника в отчёт — если не руками? Способа по сути три, и выбирать между ними — задача заказчика, то есть ваша.

## Экспорт по расписанию

Почти любая система умеет по расписанию складывать выгрузку в условленное место: файл CSV в сетевую папку или письмом на служебный адрес каждую ночь. Это самый простой способ: настраивается администратором системы без программирования. Слабое место — файл никто не «спрашивает»: если выгрузка не пришла, об этом узнают тогда, когда кто-то заметит старые цифры. Поэтому в ТЗ рядом с расписанием всегда пишут проверку: «если файла нет к 7:00 — сообщение ответственному».

## API

**API** — программный интерфейс: способ, которым одна система отвечает на запросы другой автоматически. Представьте сотрудника, который мгновенно отвечает на вопросы вида «дай список вакансий, закрытых в декабре» — только этот сотрудник никогда не устаёт, не уходит в отпуск и отвечает за доли секунды. Запрос к API отправляет не человек, а программа — например, та, что собирает ваш отчёт: она сама спрашивает у ATS свежие данные при каждом запуске. В отличие от экспорта, данные всегда актуальны на момент вопроса, а не на момент последней выгрузки.

Вам не нужно уметь программировать запросы к API. Нужно другое: знать, что такой способ существует, и спрашивать о нём поставщика системы. Фраза для переговоров: «Есть ли у вашей системы API или выгрузка в CSV по расписанию?» Ответ «выгружайте вручную из интерфейса» означает, что автоматизировать путь данных из этой системы не получится — и это аргумент при выборе системы.

## Коннекторы BI

Третий способ вы уже видели в модуле 4: DataLens подключается к базе данных напрямую. Если данные уже лежат в базе (как данные «Ромашки» в песочнице курса), между ними и дашбордом вообще нет ручного звена: обновились данные — обновился дашборд. Готовый коннектор «BI — база» или «BI — сервис» закрывает задачу «свежие цифры на экране» без единой выгрузки, и просить у поставщика BI-инструмента стоит именно его.

## «Интеграция» через человека

Четвёртый способ упоминаем, чтобы вы узнавали его в лицо: «Оля из поддержки ATS присылает нам выгрузку по вторникам». Это не интеграция, а договорённость с Олей. Она ломается в отпуск Оли, при её увольнении и в любой вторник, когда у неё завал. Все беды «файлика Маши» из урока про HR-системы относятся и сюда — просто Маша теперь на стороне поставщика. Если сегодня данные ходят через человека, первый пункт автоматизации — заменить это звено экспортом по расписанию или API.

В практике модуля, выбирая способ доставки данных для отчёта по текучести, называйте способ и проверку его отказа — этого достаточно, чтобы исполнитель понял задачу.
