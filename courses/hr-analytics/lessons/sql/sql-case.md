# Кейс: данные лежат в базе, а не в Excel

Утро понедельника. Директор просит: «Пришлите свежие цифры по увольнениям — сколько ушло с начала года и из каких отделов». У вас есть выгрузка из 1С… от прошлой среды. Заказываете новую — кадровик занят до обеда, потом файл едет по почте, потом вы его чистите. К вечеру цифры готовы — и уже снова вчерашние, потому что сегодня подписали ещё одно заявление.

Проблема не в вас и не в Excel. Просто данные о людях живут не в файлах, а в базах данных: кадровый учёт — в базе 1С, кандидаты — в базе ATS. Любая выгрузка — это копия, которая устаревает в момент, когда её сделали. А «пришлите свежие цифры» приходит каждый день.

Выход — спрашивать у базы напрямую, самому. Для этого существует SQL (читается «эс-ку-эль») — язык запросов к базам данных. На нём вы пишете, *что* хотите получить, — а база сама находит и отдаёт ответ. Почти каждый запрос модуля начинается со слова SELECT — «выбери».

Этот модуль — про SQL с нуля: как устроена база, как читать её схему и как задавать ей вопросы. Уже через несколько уроков вы посчитаете число работающих сотрудников одной строкой, а к концу модуля — текучесть «Ромашки» одним запросом, без единой выгрузки.
