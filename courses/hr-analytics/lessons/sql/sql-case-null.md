# CASE и NULL: категории и пустые значения

Руководитель не хочет читать `fte = 0.50` или пустую ячейку в дате — он хочет видеть слова: «частичная занятость», «в работе», «закрыта». Разложить значения по понятным категориям прямо в запросе умеет **CASE** — конструкция «если — то».

## CASE: если — то — иначе

```sql
select case
         when fte < 1 then 'частичная занятость'
         else 'полная занятость'
       end as rezhim,
       count(*)
from employees
where termination_date is null
group by rezhim;
```

CASE проверяет условия по порядку: подошло первое `when` — берётся его `then`, не подошло ни одно — берётся `else`, и всё закрывается словом `end`. Результат — обычный столбец, ему можно дать имя через `as` и даже группировать по нему (Postgres разрешает ссылаться на псевдоним в GROUP BY). У «Ромашки» получится 117 работающих на полной занятости и 3 — на частичной.

Веток `when` может быть сколько угодно — они проверяются сверху вниз, и срабатывает первая подходящая. Так категории стажа («до года», «1–3 года», «больше 3 лет») делаются одним столбцом.

## NULL не равен ничему — даже самому себе

Теперь главная ловушка модуля. Попробуйте посчитать открытые вакансии так:

```sql
select count(*) from vacancies where closed_on = null;
```

Ответ — 0. Хотя открытые вакансии есть. NULL — это не значение, а отметка «неизвестно / не заполнено», и любое сравнение с ним через `=` или `<>` не даёт ни истины, ни лжи — строка просто не проходит фильтр. Единственный честный способ спросить про пустоту вы уже знаете по урокам о WHERE: `is null` и `is not null`. В ветке `when` это работает точно так же: `when closed_on is null then 'в работе' else 'закрыта'`.

## COALESCE: возьми первое непустое

Частая задача: посчитать стаж и уволенным, и работающим. У уволенных стаж — до даты ухода, у работающих даты ухода нет. **COALESCE** возвращает первый непустой аргумент из списка:

```sql
select full_name,
       coalesce(termination_date, date '2025-12-31') - hire_date as dney_v_kompanii
from employees;
```

Для уволенного возьмётся его `termination_date`, для работающего — дата среза 31 декабря 2025 года. Одна строка вместо двух запросов.

## Агрегаты и NULL: COUNT(столбец) не то же, что COUNT(*)

`count(*)` считает строки. `count(столбец)` считает строки, где столбец **не пуст**:

```sql
select count(*), count(closed_on) from vacancies;
```

Вернётся 55 и 51: вакансий всего 55, закрытых — 51. Разница и есть открытые. Это не подвох, а приём: число заполненных значений без единого WHERE. Так же ведёт себя AVG — среднее считается только по непустым значениям, поэтому `avg(closed_on - opened_on)` честно усредняет сроки закрытых вакансий и не спотыкается об открытые.

Но у той же черты есть обратная сторона: если вы считали `count(termination_date)` в надежде получить всех сотрудников — вы получите только уволенных, и запрос опять не скажет об этом ни слова. С NULL всегда так: он не роняет запрос, он молча меняет ответ. Поэтому про каждый столбец, где пустота возможна, стоит один раз спросить себя: что я хочу делать с NULL — считать, пропускать или заменять?
