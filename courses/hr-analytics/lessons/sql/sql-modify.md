# INSERT и UPDATE: аккуратно меняем данные

Специалист по кадрам приносит вам список правок: нового сотрудника внесли в систему, у другого в базе опечатка в должности. До сих пор вы базу только читали — SELECT ничего не меняет, им нельзя ничего сломать. Сегодняшние две команды — меняют. Поэтому урок не только про синтаксис, но и про аккуратность.

## INSERT: добавить строку

**INSERT** добавляет в таблицу новые строки:

```sql
insert into departments (id, name)
values (9, 'Обучение и развитие');
```

После `into` — таблица и список столбцов, после `values` — значения в том же порядке. Столбцы, которых нет в списке, получат свои значения по умолчанию — так, у нового сотрудника `fte` сам станет 1.00, если его не указать. Перечислять столбцы явно — хорошая привычка: запрос переживёт изменение таблицы и его сможет прочитать человек.

## UPDATE: изменить существующее

**UPDATE** меняет значения в строках, которые прошли условие:

```sql
update vacancies
set closed_on = date '2025-12-30'
where id = 55;
```

`set` говорит, что менять, `where` — у кого. И вот главное правило урока: **WHERE в UPDATE — не украшение**. Запустите тот же запрос без него — и дата закрытия проставится всем 55 вакансиям сразу, включая открытые. UPDATE без WHERE — это команда «измени всю таблицу», и база выполнит её молча, не переспросив. В настоящих рабочих системах у такой ошибки есть страховка — изменение можно откатить, пока его не подтвердили; но страховка не отменяет привычки: сначала WHERE, потом всё остальное.

Приём аккуратного аналитика: прежде чем менять, посмотрите, кого заденет. Напишите SELECT с тем же самым WHERE, убедитесь, что вернулась ровно та строка (или ровно те строки), которые вы имели в виду, — и только потом превращайте его в UPDATE. Тридцать секунд, которые спасают таблицу.

## Как это проверять в песочнице

Честное предупреждение про устройство практики: перед **каждой** попыткой песочница пересоздаётся с чистыми данными. Это удобно — невозможно ничего испортить насовсем, — но значит, что ваш UPDATE нельзя запустить, а потом отдельной попыткой посмотреть результат: вторая попытка начнёт с чистого листа. Изменение и проверку пишут в одной отправке, друг за другом:

```sql
update vacancies set closed_on = date '2025-12-30' where id = 55;
select id, position, closed_on from vacancies where id = 55;
```

Показывается результат последнего оператора — вы увидите строку уже изменённой. Кстати, ровно так же — «изменил и тут же перечитал» — проверяют правки и во взрослых системах.

Движок сравнит состояние базы после вашего решения с эталонным: заденете лишние строки — не зачтётся, даже если нужная строка изменена правильно. WHERE решает всё.
