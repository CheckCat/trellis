# Ищем грязь: дубли, пропуски, аномалии

Рекрутер выгрузил отклики из ATS в таблицу `ats_raw` — 47 строк, шесть текстовых столбцов: `fio`, `telefon`, `data_otklika`, `vakansiya`, `istochnik`, `etap`. В отличие от остальных таблиц «Ромашки», эта — сырая: без ключей, без типов, как выплюнула система. Считать по ней что-либо до проверки качества нельзя — во втором модуле вы чистили такие выгрузки руками, теперь научимся находить грязь запросами. Запрос не устаёт и не пропускает: он проверит и 47 строк, и 47 тысяч одинаково.

## Полные дубли: GROUP BY + HAVING

Строка, попавшая в выгрузку дважды, удвоит любые подсчёты. Ищется она группировкой по всем столбцам сразу:

```sql
select fio, telefon, data_otklika, vakansiya, istochnik, etap, count(*)
from ats_raw
group by fio, telefon, data_otklika, vakansiya, istochnik, etap
having count(*) > 1;
```

Каждая группа — уникальная комбинация значений; `having count(*) > 1` оставляет те, что встретились больше раза. В `ats_raw` таких три — три полных дубля.

## Скрытые повторы: count(*) против count(distinct)

Полные дубли — грязь заметная. Хуже повторы, где строки различаются написанием. Быстрый детектор — сравнить число строк с числом уникальных значений столбца:

```sql
select count(*), count(distinct telefon) from ats_raw;
```

47 против 42: пять телефонов встречаются дважды. Причём полных дублей было три — значит, ещё два повтора прячутся в строках, которые чем-то различаются. В нашей выгрузке это люди, внесённые дважды с разным написанием имени: «Родионова Ксения Викторовна» и «родионова ксения викторовна». Группировка по `fio` такое не поймала бы — для базы это разные строки. Отсюда правило: дубли ищут по самому надёжному столбцу. Телефон надёжнее имени: большие буквы и лишние пробелы ему не грозят — в нашей выгрузке повторы номера совпадают посимвольно, а имена «поплыли».

## Пусто — не всегда NULL

Проверим незаполненный этап:

```sql
select count(*) from ats_raw where etap is null;   -- 0
select count(*) from ats_raw where etap = '';      -- 7
```

NULL-строк нет, а пустых — семь. В сырых выгрузках «пусто» часто оказывается пустой строкой `''`, а не NULL: система записала «ничего» как текст нулевой длины. Проверять надо обе формы пустоты — иначе отчёт честно скажет «пропусков нет», глядя на семь пропусков.

## Лишние пробелы и разнобой форматов

Пробел в начале имени глазом не виден, а сортировку и поиск ломает. Детектор — сравнение длины до и после `trim()`, функции, срезающей пробелы по краям:

```sql
select count(*) from ats_raw where length(fio) <> length(trim(fio));
```

Десять строк. А в `data_otklika` даты записаны тремя форматами сразу: `07.02.2025`, `2025-03-11`, `27 февраля 2025`. Такой столбец — текст, сравнивать его с датами нельзя, пока не приведёшь к одному виду; само приведение — работа кропотливая и за рамками урока. Здесь важно другое: **заметить**. Аналитик, который перед подсчётом прогнал четыре проверки — дубли, скрытые повторы, пустоты, форматы, — знает, чему в его цифрах можно верить. Это пять минут, которые отличают отчёт от угадывания.
