# GROUP BY и HAVING: разрезы по отделам

«Увольнений за 2025 год — 23». Хорошо, а *по каким основаниям*? Любой ответ-число немедленно рождает вопрос «а в разрезе?» — по отделам, по причинам, по источникам. Разрез делает **GROUP BY**: строки раскладываются на группы, и агрегат считается для каждой группы отдельно.

```sql
select reason, count(*)
from terminations
where term_date between date '2025-01-01' and date '2025-12-31'
group by reason
```

| reason | count |
|---|---|
| по собственному желанию | 15 |
| истечение срочного договора | 4 |
| не прошёл испытательный срок | 2 |
| соглашение сторон | 1 |
| инициатива работодателя | 1 |

Читайте запрос по шагам: `where` отобрал увольнения 2025 года, `group by reason` разложил их на кучки по основанию, `count(*)` посчитал каждую кучку. Пять групп — пять строк ответа.

## Главное правило GROUP BY

В списке `select` при группировке может стоять только два вида столбцов: те, по которым группируете, и агрегаты. Написать `select reason, term_date, count(*) ... group by reason` не выйдет — в группе «по собственному желанию» пятнадцать разных дат, и база честно откажется выбирать одну из них за вас, а сообщит об ошибке. Это правило ловит недодуманные запросы раньше, чем они соврут.

Агрегатов на группу можно навесить сколько угодно: `select department_id, count(*), min(hire_date) from employees group by department_id` — размер каждого отдела и его самый давний наём.

## HAVING: фильтр по итогам группы

А если нужны не все группы? Скажем, из оснований за все три года оставить только частые:

```sql
select reason, count(*)
from terminations
group by reason
having count(*) >= 5
```

Останутся 4 строки: «по собственному желанию» (38), «истечение срочного договора» (11), «соглашение сторон» (7), «не прошёл испытательный срок» (7) — редкая «инициатива работодателя» отсеялась. **HAVING** — это условие *на группу*, поэтому в нём можно использовать агрегат.

Различие с `where` принципиальное:

- `where` работает **до** группировки и отбирает *строки* — «только увольнения 2025 года»;
- `having` работает **после** и отбирает *группы по их итогам* — «только основания, встретившиеся 5 и более раз».

Попытка написать `where count(*) >= 5` закончится ошибкой: пока `where` смотрит на строку, никаких итогов ещё не существует. Проверочный вопрос себе: моё условие про отдельную запись или про сводное число? Первое — `where`, второе — `having`.

Ещё пример на другой таблице: должности, на которых за историю компании побывало не меньше 20 человек, — `select position, count(*) from employees group by position having count(*) >= 20` — их всего две: «оператор линии» (29) и «менеджер по продажам» (28).
