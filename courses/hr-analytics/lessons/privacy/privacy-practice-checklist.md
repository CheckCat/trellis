# Практика: чек-лист приватности для отчёта

Соберём модуль в один рабочий инструмент — пять вопросов, которые вы задаёте каждому отчёту перед отправкой. Порядок не случайный: первые вопросы убирают лишнее, последние — проверяют, куда и как поедет то, что осталось.

1. **Минимизация.** Какова цель отчёта — и какие поля можно вычеркнуть без ущерба для неё? Каждое оставшееся поле должен оправдывать ответ «без него цель недостижима».
2. **Агрегация.** Можно ли ответить на вопрос отчёта итогами по группам вместо строк про людей? Если да — обезличить и показывать группы.
3. **Размер групп.** Есть ли в отчёте группы меньше порога k-анонимности? Маленькие группы объединить или убрать.
4. **Круг получателей.** Кто в списке рассылки и зачем это каждому из них? «Всем руководителям» — не ответ; у каждого получателя должна быть задача, для которой отчёт нужен.
5. **Канал передачи.** Как отчёт едет к получателям? Корпоративная почта и внутренние хранилища — да; личные мессенджеры, внешние сервисы и «скину в общий чат» — нет.

Теперь верните долг открывающему кейсу: таблица «ФИО, отдел, должность, оклад, дата рождения» для знакомой из другой компании не проходит уже первый вопрос — для «бенчмарка по отделам» не нужно ни одно из полей про конкретных людей, — а просьба извне проваливает и четвёртый: у чужой компании нет никакого основания получать данные сотрудников «Ромашки». Ответ «нет» собирается из чек-листа за минуту.

## Кейс для зачёта

К квартальному собранию руководителей готов файл: **список уволившихся из «Ромашки» за квартал — ФИО, причина увольнения, оклад, возраст; файл уходит по корпоративной почте всем начальникам отделов**. Цель собрания — обсудить, почему люди уходят и что с этим делать.

Прогоните файл по чек-листу и отметьте в квизе всё, что нужно исправить перед отправкой. Каждый вариант — самостоятельное действие: оценивайте каждое отдельно, а не ищите «самое главное».
