# HR-аналитика с нуля

Статус: **написан целиком** (`version: 1.0.0`, 2026-09-29). 9 модулей, 74 урока; план
курса — в `skills.yaml`, данные сквозного примера — в `sandbox/` и `data/` (генератор —
`tools/generate-data.mjs`). Формат пакета — см. `courses/README.md`.

## Бриф

- **Тема.** После курса человек без аналитического опыта может сам ответить на типовой
  вопрос руководителя про людей («у нас нормальная текучесть?», «почему долго нанимаем?»):
  достать данные, посчитать метрику, показать её на дашборде и сформулировать вывод.
- **Аудитория и точка входа.** HR-специалист или начинающий аналитик. Умеет пользоваться
  компьютером и открыть таблицу; не знает ни SQL, ни статистики, ни BI. Excel видел,
  но формулами не владеет.
- **Инструменты.** Песочница курса (Postgres, модуль 3 и далее), Excel или его аналог
  (модуль 2, файлы из `data/`), Яндекс DataLens (модуль 4). Внешние инструменты движок
  не проверяет процессом — проверяет результатом (`practice.type: answer`).
- **Объём.** ~120 часов; при 6–8 часах в неделю — 4–6 месяцев. Модуль 7 — по желанию.
- **Сквозной пример.** Вымышленная ООО «Ромашка»: ~150 человек в данных за 2023–2025,
  8 отделов. Один и тот же набор данных везде: seed песочницы (`sandbox/seed.sql`),
  CSV-файлы для Excel и DataLens (`data/`), числа в теории и эталоны заданий.
  Дата среза всюду — **31 декабря 2025**; данные полностью синтетические и
  детерминированные (ни `now()`, ни `random()`).

## Решения пересборки скелета (2026-09-29)

Первый скелет писался до появления в движке `practice.type: answer` и мультивыборных
квизов. Пересборка:

1. Все задания «во внешнем инструменте с самоотметкой» переведены на `practice.type:
   answer`: ученик считает в Excel/DataLens, вписывает результат, движок сверяет с
   эталоном. Самоотметка осталась только там, где результат не сводится к числу или
   строке (написать ТЗ, собрать дашборд, сформулировать выводы).
2. Убран урок `intro-glossary`: глоссарий всех терминов заранее противоречит словарю
   курса (термин вводится своим уроком, а не списком в начале). Роль глоссария выполняет
   секция `terms` в `skills.yaml`.
3. Данные «Ромашки» создаются **до контента** (фаза 3), а не «вместе с модулем 3»:
   из них считаются и числа модуля 1, и Excel-файлы модуля 2, и эталоны SQL-заданий.
4. SQL-задания на `SELECT` проверяются сравнением результата с эталонным запросом
   (`expected`), задание на изменение данных — сравнением состояния базы с эталонным
   решением (`solution`), а не только `check`-предикатом.
5. Добавлен `skills.yaml`: карта умений, словарь терминов с `forms`/`mentioned_before`
   и `grants` для SQL-приёмов — линт держит порядок «сначала объясни, потом требуй».

## Соглашения

- `id` модулей и уроков — стабильные слаги (на них завязан прогресс), нумерация живёт
  только в заголовках.
- Каждый модуль открывается коротким уроком-кейсом с реальным HR-вопросом (зачёт
  самоотметкой — это мотивация, а не материал).
- Квиз — один вопрос на урок; урок не несёт квиз и проверяемую практику одновременно
  (квиз побеждает, практика осталась бы необязательной).
- Файлы для Excel/DataLens лежат в `data/` внутри пакета курса (платформа файлов не
  отдаёт; путь на диске ученика настоящий, уроки называют его целиком). CSV — с
  разделителем `;` и BOM, чтобы русский Excel открывал их двойным щелчком.
- Песочница `romashka` (`sandbox/seed.sql`): departments, employees, terminations,
  vacancies, applications, salary_history + «грязная» таблица ats_raw для уроков про
  качество данных. Грязь только в ats_raw — основные таблицы чистые, чтобы числа
  уроков не плыли.
- Все ключевые числа курса считаются запросами по seed и записываются в этот README
  (секция «Ключевые числа», появится в фазе 3) — рядом с запросом, которым получены.

## Ключевые числа (фаза 3)

Данные генерируются `tools/generate-data.mjs` (детерминированный PRNG, зерно 20251231):
один прогон пишет и `sandbox/seed.sql`, и `data/*.csv`. Всё, что попадает в теорию и в
эталоны заданий, посчитано запросами по этим данным в одноразовой базе:

```bash
docker compose exec -T postgres psql -U postgres -d postgres \
  -c 'drop database if exists scratch' -c 'create database scratch'
docker compose exec -T postgres psql -q -U postgres -d scratch < courses/hr-analytics/sandbox/seed.sql
```

Соглашение о датах: `termination_date` — последний рабочий день; сотрудник числится на
дату D, если `hire_date <= D and (termination_date is null or termination_date >= D)`.
Среднесписочная численность в курсе — упрощённая: среднее из численностей на конец
каждого из 12 месяцев.
