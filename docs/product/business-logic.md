
## Goal

Trellis (рабочее название, альтернатива — Rostok) — локальный, бесплатный, самостоятельно разворачиваемый сервис для прохождения учебных курсов. Ядро специальность-агностично: движок (прогресс, квизы, импорт/экспорт, Docker-оркестрация) не содержит знаний о конкретном курсе. Курс подключается как отдельный контент-пакет — строго валидируемые данные, а не код. Первый курс — пилот для обкатки платформы (генерируется в отдельном рабочем процессе, вне этого сервиса); после него курсов может быть несколько, разных тематик.

Всё работает на компьютере пользователя: нет облачного сервера, нет отправки данных наружу.

Техническое имя проекта — Trellis (compose-проект, пакеты, volume); маркетинговое имя может быть выбрано позже. <!-- clarify 2026-09-15: Q-012 -->

## Roles

- Учащийся — единственная роль MVP: один человек проходит один курс на одном компьютере.

## Core scenarios

- **Запуск платформы**: единый отказоустойчивый скрипт для Windows поднимает весь стек и сообщает готовый адрес; браузер не открывается автоматически (детали — в technical-solutions.md).
- **Прохождение курса**: пользователь идёт по модулям → урокам; урок содержит текстовый контент и/или квиз.
- **Квиз**: вопрос с вариантами ответа и единственно верным вариантом. При выборе неверного — подсветка и объяснение, почему он неверен; попытки не блокируются до выбора верного; при верном — визуальное подтверждение.
- **Практика через декларируемые песочницы**: если курсу нужна практическая среда (например, реальная БД для SQL-упражнений), курс сам объявляет её в своей конфигурации; ядро умеет поднимать объявленные ресурсы, не зная, что это за ресурс конкретно.
- **Подключение курса**: ядро валидирует контент-пакет по схеме до показа пользователю; работает с любым количеством модулей/уроков без хардкода названий. Замена или обновление курса не ломает сохранённый прогресс по другому курсу.
- **Перенос прогресса между компьютерами** (например, дом/работа): экспорт состояния в переносимый файл с меткой времени последнего сохранения; при импорте — предупреждение, если импортируемый файл старше локального прогресса, чтобы не затереть новые данные старыми.
- Наполнение песочницы: курс декларирует seed-скрипты SQL (DDL + данные); ядро выполняет их от роли песочницы (не суперпользователя) при подключении курса; операция «сбросить песочницу» пересоздаёт схему из seed. <!-- clarify 2026-09-15: Q-002 -->
- Обновление того же курса: прогресс привязан к стабильным id модулей/уроков — совпавшие id остаются пройденными, новые считаются не пройденными, удалённые игнорируются; сброса прогресса при обновлении нет. <!-- clarify 2026-09-15: Q-004 -->
- Модель прогресса (минимум): статус урока — не начат/пройден; текстовый урок проходится явной отметкой «пройдено», урок с квизом — верным ответом; курс пройден = все уроки пройдены; история попыток квизов не хранится. <!-- clarify 2026-09-15: Q-005 -->
- Формат экспорта: версионированный app-level JSON только с данными прогресса; метка времени последнего сохранения и id/версии курсов — внутри файла. <!-- clarify 2026-09-15: Q-006 -->
- Доставка курса: локальная директория courses/, примонтированная в compose; валидация папки курса выполняется при старте, до показа курса пользователю; повторное сканирование — по явному действию. <!-- clarify 2026-09-15: Q-008 -->
- Импорт файла с прогрессом по курсу, не установленному локально: импортируется всё; прогресс неустановленных курсов хранится и активируется при появлении курса. <!-- clarify 2026-09-15: Q-009 -->
- Повторное прохождение уже пройденного урока/квиза разрешено; статус «пройден» не откатывается. <!-- clarify 2026-09-15: Q-010 -->
- Выполнение и зачёт практики: SQL пишется во встроенном в урок редакторе (готовый компонент CodeMirror); запрос выполняет backend в песочнице, результат или ошибка Postgres показываются как есть. Задание может нести check-запрос в manifest'е — после попытки движок выполняет его и трактует ответ как «зачтено/не зачтено»; задание без check засчитывается самоотметкой. <!-- clarify 2026-09-15: Q-003 -->

## MVP scope

Входит:
- Ядро + один пилотный контент-пакет; один пользователь, один компьютер, только `localhost`.
- Формат курса — директория-пакет: manifest.yaml (метаданные: название, версия, требуемые песочницы; структура модулей → уроков со стабильными id; квизы; задания практики с опциональным check-запросом; ссылки на контент) + текст уроков отдельными Markdown-файлами; manifest валидируется по схеме. <!-- clarify 2026-09-15: Q-007 -->
- Прогресс в локальной БД; экспорт/импорт прогресса.
- Песочница практики для БД: отдельная схема/роль с правами только на эту схему — пользователь физически не может испортить данные платформы через практические задания.
- Механизм песочниц проектируется как интерфейс, где БД — лишь одна из реализаций (без полноценной системы плагинов).
- Дизайн: минималистичный, дружелюбный интерфейс; базовая палитра — мягкие зелёные тона. <!-- clarify 2026-09-15: восстановлено из раздела 6 исходника (пропуск упаковки brief) -->

Не входит (долгосрочное видение, MVP не должен ему противоречить):
- SaaS с созданием курсов через ИИ, marketplace с оценками, тарифы, комиссия с продаж, «коннекторы» к внешним сервисам (по аналогии с коннекторами Claude).
- Electron, удалённый сервер, любой облачный компонент.

## Success criteria

- Один человек может пройти один курс целиком на одном компьютере.
- Второй/третий курс добавляется без переделки ядра.
- Архитектура не противоречит долгосрочному видению (второй тип песочницы не потребует переписывать первый).
- Пересборка контейнеров не приводит к потере прогресса.
