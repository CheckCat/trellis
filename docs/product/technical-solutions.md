
## Stack

- backend: fastify
- frontend: react
- deploy: docker-compose
- db: postgresql

## Services

- backend — API движка (прогресс, квизы, валидация и подключение контент-пакетов, экспорт/импорт).
- frontend — React SPA, UI прохождения курса и квизов; встроенный SQL-редактор практики на CodeMirror (sql-режим). <!-- clarify 2026-09-15: Q-003 -->
- postgres — хранение прогресса пользователя; обязательно именованный volume (иначе пересборка контейнеров = потеря прогресса).

Песочница практики (SQL) — не отдельный сервис/контейнер: отдельная схема/роль внутри того же Postgres-инстанса с правами, ограниченными только этой схемой.

## Auth

Без аутентификации в MVP: один неявный локальный пользователь; backend слушает только 127.0.0.1, порты наружу не публикуются. Изоляция практики — ролями/схемами Postgres (песочница), а не user-auth. <!-- clarify 2026-09-15: Q-001 -->

## Deploy

- Весь стек поднимается через `docker-compose`, только локально (`localhost`), без Electron и без удалённого сервера.
- Целевая платформа пользователя — Windows: единый скрипт запуска `.bat`/`.ps1` (не `.sh`), отказоустойчивый, каждый шаг с понятным сообщением, а не тихим зависанием:
  1. проверить, запущен ли Docker Desktop; если нет — попытаться запустить и дождаться готовности демона;
  2. `docker-compose up`;
  3. дождаться готовности всего стека: healthcheck Postgres, backend (`/health`), frontend (HTTP 200);
  4. вывести готовый адрес `http://localhost:<порт>` — браузер автоматически НЕ открывается.

  Все сообщения скрипта — человекочитаемые, в стиле инсталлера: не-разработчик должен понимать, что происходит на каждом шаге. <!-- clarify 2026-09-15: Q-013 -->
- Для разработки на не-Windows отдельного скрипта нет: ручной `docker compose up`; `.ps1`/`.bat` — только пользовательская упаковка. <!-- clarify 2026-09-15: Q-011 -->
