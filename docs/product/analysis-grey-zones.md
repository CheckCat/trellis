# Analysis: grey zones

## Принятые решения (X, а не Y)

- **Docker + браузер, а не Electron** — весь стек через `docker-compose`, UI в браузере на `localhost`.
- **Скрипт запуска `.bat`/`.ps1`, а не `.sh`** — целевая платформа пользователя Windows.
- **Песочница SQL — отдельная схема/роль в том же Postgres-инстансе, а не отдельный инстанс** — права ограничены схемой, данные платформы недоступны из практики.
- **Курс — данные со схемой, а не код/свободный текст** — валидация до показа пользователю.
- **Песочницы — интерфейс, а не хардкод Postgres** — Postgres лишь одна из реализаций; без полноценной системы плагинов сейчас.
- **Backend — Fastify (Node/TypeScript), а не Express/PostgREST** — источник оставлял вопрос открытым (Node/Express vs PostgREST); оператор при упаковке brief выбрал Fastify (2026-09-15). Под этот выбор в mvp-плагин добавлена поддержка `backend: fastify`.
- **Deploy — docker-compose локально, а не docker-dokploy** — allowlist mvp-плагина содержал только docker-dokploy, что противоречило требованию «только localhost»; оператор выбрал docker-compose, поддержка добавлена в плагин (2026-09-15).
