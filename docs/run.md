# Запуск Trellis

Trellis работает целиком на вашем компьютере: никакого сервера в интернете,
никакой отправки данных наружу. Платформа открывается в обычном браузере по
адресу вида `http://localhost:3000`, но доступна только с этой машины.

Из всего софта нужен **только Docker Desktop**. Node.js ставить не надо: он
нужен самой платформе, но живёт внутри контейнеров — Docker скачает его сам.

---

## 1. Что нужно один раз

| Что | Зачем |
|---|---|
| Windows 10/11 (64-бит), macOS 12+ или Linux | поддерживаемые системы |
| [Docker Desktop](https://www.docker.com/products/docker-desktop/) | Trellis работает в контейнерах; установщик сам включит WSL2 и попросит перезагрузку |
| ~4 ГБ свободного места на диске | образы контейнеров и база данных |
| Интернет — только на первый запуск | Docker скачивает базовые образы (Postgres, Node, nginx) |

После установки Docker Desktop перезагрузите компьютер (на Windows это
обязательно) и убедитесь, что в окне Docker Desktop написано **Engine
running**. Дальше Docker можно не открывать — скрипт запустит его сам, если
он не запущен.

## 2. Три команды, которые нужны в жизни

Все скрипты лежат в папке `scripts/stack/` — по три файла на каждую команду
(для Windows, для macOS/Linux и обёртка для двойного щелчка).

| Что нужно сделать | Windows (двойной щелчок) | macOS / Linux | Если есть Node |
|---|---|---|---|
| Запустить платформу | `scripts\stack\start.bat` | `./scripts/stack/start.sh` | `npm start` |
| Пересобрать после обновления проекта | `scripts\stack\rebuild.bat` | `./scripts/stack/rebuild.sh` | `npm run stack:rebuild` |
| Остановить | `scripts\stack\down.bat` | `./scripts/stack/down.sh` | `npm run stack:down` |

Все три варианта одной строки делают ровно одно и то же и печатают одно и то
же. Колонка «если есть Node» — удобство для разработчиков; пользователю Node
не нужен.

Из PowerShell то же самое вызывается напрямую:

```powershell
.\scripts\stack\start.ps1
.\scripts\stack\rebuild.ps1
.\scripts\stack\down.ps1
```

`.bat`-файлы — это обёртки над одноимёнными `.ps1`: они подбирают подходящий
PowerShell, разрешают запуск неподписанного скрипта только для этого запуска
и не дают окну закрыться раньше, чем вы прочитаете, что в нём написано.

## 3. Запуск

Откроется чёрное окно консоли, в котором по шагам написано, что происходит:

```
  [1/5] Проверяю Docker
  [2/5] Проверяю настройки (файл .env)
  [3/5] Собираю и запускаю платформу
  [4/5] Жду, пока платформа будет готова
  [5/5] Готово
```

- **Первый запуск идёт дольше остальных** — несколько минут: контейнеры
  собираются с нуля. В окне будет много технического вывода Docker, читать его
  не нужно.
- Последующие запуски — обычно меньше минуты.
- В конце скрипт печатает адрес:

  ```
      Открой в браузере:  http://localhost:3000
  ```

  **Браузер не открывается автоматически** — это сделано намеренно: адрес
  печатается только тогда, когда платформа действительно готова отвечать, а не
  «вот-вот будет готова». Скопируйте адрес в браузер сами.

- Окно консоли после этого можно закрыть: платформа продолжает работать в
  фоне, внутри Docker.

## 4. Пересборка после обновления проекта

Если вы обновили папку проекта (забрали новую версию из репозитория,
распаковали новый архив) — запускайте **пересборку**, а не обычный запуск.

Обычный запуск тоже пересобирает изменившееся, но пользуется кешем слоёв
Docker. Кеш почти всегда прав, но иногда оказывается умнее, чем надо: слой с
установкой зависимостей переиспользуется, потому что Docker не видит причины
собирать его заново, — и получается новая версия кода со старыми
зависимостями. Разбираться, когда именно так вышло, необязательно:
пересборка чинит это без разбирательств.

| Windows | macOS / Linux | Если есть Node |
|---|---|---|
| `scripts\stack\rebuild.bat` | `./scripts/stack/rebuild.sh` | `npm run stack:rebuild` |

Что она делает:

```
  [1/7] Проверяю Docker
  [2/7] Проверяю настройки (файл .env)
  [3/7] Останавливаю текущие контейнеры
  [4/7] Собираю образы заново, без кеша
  [5/7] Запускаю платформу
  [6/7] Жду, пока платформа будет готова
  [7/7] Готово
```

**Прогресс не теряется.** Том `trellis_pgdata` пересборка не трогает: база
остаётся на месте, миграции ядра накатываются на неё, весь пройденный
материал сохраняется. Пересборка занимает столько же, сколько самый первый
запуск (все слои собираются с нуля), и требует интернета.

## 5. Остановка

| Windows | macOS / Linux | Если есть Node |
|---|---|---|
| `scripts\stack\down.bat` | `./scripts/stack/down.sh` | `npm run stack:down` |

Удаляет контейнеры и сеть. **Прогресс сохраняется** — он живёт в именованном
томе Docker `trellis_pgdata`, который переживает и остановку, и пересборку.
Следующий запуск поднимет платформу ровно с тем же содержимым.

Удалить данные можно только отдельной явной командой — см. раздел
«Полный сброс».

## 6. Настройки: файл `.env`

При первом запуске скрипт сам создаёт в корне проекта файл `.env` (по образцу
`.env.example`) и придумывает случайные пароли для внутренней базы данных.
Ничего заполнять руками не нужно.

Что в нём можно менять:

| Строка | Значение по умолчанию | Когда менять |
|---|---|---|
| `FRONTEND_PORT` | `3000` | если порт занят другой программой |
| `BACKEND_PORT` | `3001` | то же |
| `POSTGRES_PORT` | `5433` | то же |
| `POSTGRES_PASSWORD`, `APP_DB_PASSWORD`, `SANDBOX_DB_PASSWORD` | случайные | см. ниже — отдельная процедура |

В паролях допустимы только латинские буквы, цифры и знаки `.` `_` `~` `-`.
Символы `@ : / ? # %` и пробел ломают строку подключения к базе — скрипт
проверяет это до запуска и скажет об этом прямо.

Файл `.env` не попадает в git и остаётся только у вас на диске.

## 7. Смена паролей базы данных

**Важно:** база запоминает пароли ролей один раз — при самом первом запуске, на
пустом хранилище. Если просто поменять пароль в `.env` и перезапустить
платформу, ядро перестанет входить в базу и будет падать по кругу.

Чтобы поменять пароль без потери прогресса:

1. Откройте `.env`, впишите новые пароли.
2. Откройте PowerShell в папке проекта (правый клик по пустому месту в папке →
   «Открыть в терминале») и выполните:

   ```powershell
   .\scripts\stack\start.ps1 -SyncPasswords
   ```

   На macOS/Linux: `./scripts/stack/start.sh --sync-passwords`
   (с Node: `npm start -- --sync-passwords`).

Эта команда приводит пароли ролей `trellis_app`, `trellis_sandbox` и
`postgres` внутри базы к тем, что сейчас записаны в `.env`, перезапускает ядро
и продолжает обычный запуск. Прогресс при этом не теряется.

Тот же ключ спасает, если пароль в `.env` изменили случайно (или потеряли
файл и создали новый): `.env` — источник правды, база подстраивается под него.

## 8. Если что-то пошло не так

Скрипт не зависает молча: он либо доводит запуск до конца, либо печатает, что
именно сломалось. Технические подробности (журнал контейнера) он печатает
первыми, а понятное объяснение — последним, сразу перед приглашением нажать
клавишу. **Читайте снизу вверх.**

| Что написано | Что это значит | Что делать |
|---|---|---|
| `Docker не установлен` | Docker Desktop не стоит или не виден консоли | установить [Docker Desktop](https://www.docker.com/products/docker-desktop/), перезагрузиться |
| `Docker Desktop не поднялся за 180 сек` | движок не стартовал | открыть Docker Desktop и прочитать, что он просит (обычно — обновить WSL2 или перезагрузиться) |
| `нужный порт уже занят другой программой` | на порт 3000/3001/5433 уже кто-то сел | поменять соответствующий `*_PORT` в `.env` и запустить снова |
| `Docker не смог скачать нужные образы из интернета` | нет связи с hub.docker.com | проверить интернет; при работе через прокси/VPN — настроить его в Docker Desktop → Settings → Resources → Proxies |
| `Ядро не может войти в базу: пароль в .env не совпадает…` | пароль поменяли после первого запуска | `.\scripts\stack\start.ps1 -SyncPasswords` (раздел 7) |
| `Ядро не смогло применить миграции базы` | база в состоянии, которого ядро не ожидает | причина названа в журнале выше; крайняя мера — полный сброс (раздел 9) |
| `База данных … не стало готовым` | Postgres не поднялся | прочитать журнал выше; `docker compose logs postgres` покажет его целиком |
| Окно консоли мелькнуло и закрылось | запускали `.ps1` двойным кликом | запускать надо `.bat` — он держит окно открытым |
| В браузере «Связи с ядром нет» | интерфейс работает, ядро — нет | запустить скрипт ещё раз: он дождётся ядра и объяснит причину, если ядро не поднимается |
| Изменения из новой версии не появились | образ собрался из кеша | пересобрать начисто (раздел 4) |

Полные журналы всегда доступны из папки проекта:

```powershell
docker compose logs backend     # ядро платформы
docker compose logs postgres    # база данных
docker compose logs frontend    # интерфейс
```

## 9. Полный сброс (крайняя мера)

```powershell
.\scripts\stack\down.ps1 -WithData
```

На macOS/Linux: `./scripts/stack/down.sh --with-data`
(с Node: `npm run stack:down -- --with-data`).

Удаляет контейнеры **вместе с томом `trellis_pgdata`**, то есть со всем
сохранённым прогрессом. Команда спросит подтверждение — придётся набрать
слово `УДАЛИТЬ` (или `DELETE`) целиком: восстановить данные будет неоткуда.
Перед этим выгрузите прогресс из интерфейса (экспорт даёт файл, который потом
можно импортировать обратно).

После сброса следующий запуск поднимет платформу с нуля и заново создаст
роли базы с паролями из текущего `.env`.

## 10. Для разработчиков

Лаунчеры — пользовательская упаковка, для разработки они не обязательны.
Стек поднимается и напрямую:

```bash
docker compose up -d --build
```

Проверки перед коммитом — `bash .mvp/ci-mirror.sh` (то же, что делает CI).

### Что лежит в `scripts/stack/`

| Файл | Что это |
|---|---|
| `common.sh`, `common.ps1` | общая часть: разговор с пользователем, проверки Docker и `.env`, ожидание healthcheck'ов, разбор причин отказа |
| `start.sh`, `rebuild.sh`, `down.sh` | сами команды для macOS/Linux — короткие сценарии из шагов общей части |
| `start.ps1`, `rebuild.ps1`, `down.ps1` | то же для Windows |
| `start.bat`, `rebuild.bat`, `down.bat` | точки входа для двойного щелчка; вся их логика — в `_run.bat` |
| `stack.mjs` | диспетчер для `npm start` / `npm run stack:*` |

### Почему реализаций две

`common.ps1` (Windows) и `common.sh` (macOS/Linux) — две реализации одного и
того же, и это осознанная цена. Скрипт запуска работает до того, как поднято
хоть что-то, поэтому не может полагаться ни на что, кроме встроенного в
систему: на Windows это PowerShell, на остальных — sh. Написать его один раз
на Node нельзя: тогда пользователю пришлось бы ставить Node только ради
скрипта, хотя самой платформе он не нужен.

Чтобы расхождение не прошло тихо, значения, которые обязаны совпадать
(таймауты, состав и заголовки шагов каждой команды, имена сервисов, ключи
`.env`, признаки сетевого сбоя, запрет на `down -v`), сверяет тест
`scripts/stack-parity.test.mjs` — он входит в обычный `npm test`.

`scripts/stack/stack.mjs` — не третья реализация, а диспетчер: он выбирает
нужный лаунчер по системе, переводит ключи (`--with-data` → `-WithData`) и
пробрасывает код возврата.
